# Банк ошибок: план реализации

> **Для исполнителя:** используй superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans. Шаги отмечай `- [ ]`.

**Цель:** неверно решённое упражнение возвращается через 1 день, затем через 3, и закрывается после двух верных ответов подряд; страница «Ошибки» показывает, что открыто и когда вернётся.

**Архитектура:** поверх частей 1–2. Чистое расписание в новом пакете `internal/mistakes` и `exercises.Reshuffle`; открытие и продвижение ошибки внутри транзакции `AnswerExercise`; выдача повтора в `GetNextExercise` до выбора темы; новый путь `GET /api/v1/mistakes`; страница «Ошибки» вместо заглушки. Те же `exercises`, рейтинг и события.

**Стек:** Go, pgx + sqlc, goose, OpenAPI → oapi-codegen, React + TanStack Query. Новых зависимостей нет.

**Спек:** `docs/superpowers/specs/2026-10-24-mistakes-design.md`.

## Global Constraints

- Новых зависимостей нет. SQL только в `queries/`; контракт сначала в `api/openapi.yaml`, затем `sqlc generate`, `go generate ./internal/api` (oapi-codegen в `~/go/bin`), `npm run gen:api` в `web/`; генерированное руками не правим.
- Интерфейс на русском; сверка с `DESIGN.md` и его обновление. **Исполнитель фронтенда обязан вызвать навыки `impeccable`, `web-design-guidelines`, `emil-design-eng` через Skill-инструмент** и описать это в отчёте.
- Все новые тесты сначала RED (вывод падения в отчёте), потом GREEN.
- Правила (значения из спека, дословно): первый повтор `next_due = ответ + 24 часа`; после первого верного `+ 72 часа`; закрытие при `streak = 2`; не больше 5 повторов в день (сутки в часовом поясе настроек, по умолчанию UTC); повтор выдаётся, только если два последних упражнения пользователя не были повторами; не больше одной открытой ошибки на `(user_id, sentence_id, kind)`; в списке не больше 200 ошибок, `counts.open` считает все.
- Миграция `00010` обратимая; **к настоящей базе применять только после явного «да» пользователя** и `pg_dump` (без таблиц Tatoeba, в `.cache/backups/`). До этого только временная схема; к настоящей базе допустимо чтение (SELECT, EXPLAIN). Старые неверные ответы в банк не заполняются.
- Правильный ответ клиенту до ответа не уходит; тексты из базы выводятся только текстом.
- Проверка перед каждым коммитом: `go vet ./... && go test -race ./... && golangci-lint run && gofmt -l .` (пусто); в `web/` — `npx vitest run && npx tsc -b && npm run lint && npm run build`. Коммитить только свои файлы (не `git add -A`).
- Не пушить; коммиты по-русски, в конце `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- Повтор запроса ответа по ключу не открывает вторую ошибку и не двигает серию (Task 3).
- Неверный ответ на то же предложение и вид при открытой ошибке сбрасывает её, а не создаёт вторую (Task 2 индекс, Task 3).
- Перезагрузка страницы при выданном повторе возвращает ту же копию, а не новую строку (Task 3).
- Повтор не выдаётся два раза подряд и не больше 5 в день; при нескольких наступивших выбирается самая старая (Task 1, 3).
- Перемешанные плитки повтора «порядка слов» не совпадают ни с одним допустимым ответом (Task 1).
- Ошибка по предложению, которого нет в `sentences` или уже закрытая: не 500, повтор пропускается (Task 3).
- Пустой банк: `GET /mistakes` отдаёт `[]` и нули, не `null` (Task 3, 4).
- Страница при `nextDue` в прошлом показывает «ждёт повтора», а не отрицательный срок (Task 4).
