# Авторизация Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Единственный пользователь входит по логину и паролю; сессия живёт в cookie, все будущие эндпоинты кроме `/health` закрыты проверкой сессии.

**Architecture:** Чистые функции в `internal/auth` (пароль, токен, ограничитель перебора). Контракт в `api/openapi.yaml`, из него oapi-codegen генерирует интерфейс сервера. Обработчики и middleware в `internal/httpapi` работают через узкий интерфейс над `internal/db.Queries`. Пользователя создаёт отдельная команда `cmd/createuser`.

**Tech Stack:** Go 1.27, `net/http`, pgx + sqlc (уже есть), `golang.org/x/crypto/argon2`, `golang.org/x/term`, oapi-codegen.

**Spec:** `docs/superpowers/specs/2026-10-22-auth-design.md`

## Global Constraints

- Пароль: argon2id, хеш в формате PHC (`$argon2id$...`), иначе `CHECK` в `users` отвергнет вставку.
- Cookie сессии: `HttpOnly`, `Secure`, `SameSite=Strict`, срок 30 дней. В БД только SHA-256 токена (32 байта, `bytea`).
- Токен: 32 случайных байта, base64url без паддинга.
- Параметры argon2id (решение плана): память 19456 КиБ, итераций 2, потоков 1, соль 16 байт, ключ 32 байта.
- Неверный логин и неверный пароль: одинаковый `401` с одинаковым телом; для несуществующего логина всё равно считается фиктивный хеш.
- Ограничение перебора: 5 неудач подряд с одного IP, затем `429` на 1 минуту.
- Пароль и токен не попадают в логи. Комментарии и сообщения об ошибках на русском, как в существующем коде.
- Контракт меняется сначала в `api/openapi.yaml`; сгенерированный код руками не правим. SQL только в `queries/`.
- Новых зависимостей сверх `golang.org/x/crypto`, `golang.org/x/term`, oapi-codegen не добавлять.
- Коммитить только по просьбе пользователя. Перед каждым коммитом: `go vet ./... && go test -race ./...`.

## Review Focus

- Пустой или слишком длинный логин/пароль в `POST /login` → `400`, а не панику или хеширование мегабайтов (лимит: пароль до 256 байт, логин до 32).
- Запрос без cookie, с мусорным значением cookie и с истёкшей/отозванной сессией → одинаково `401` на `/me`.
- Повторный `logout` с уже отозванной сессией и `logout` без cookie → `204`, не ошибка.
- `POST` с чужим `Origin` → `403`; `POST` без `Origin` (curl, тесты) разрешён только если `Sec-Fetch-Site` тоже не `cross-site`.
- Успешный вход сбрасывает счётчик неудач; блокировка по IP снимается через минуту и не зависит от порта клиента (`RemoteAddr` без порта).
