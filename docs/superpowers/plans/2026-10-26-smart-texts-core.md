# «Умные тексты», этап 1: ядро (склейка, `/read`, звук, слова в карточки)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native). Шаги с чекбоксами `- [ ]`.

**Goal:** страница `/read`: сервис собирает из предложений Tatoeba текст на целевом уровне понимания (по умолчанию 85 %), его можно читать и слушать (синтез речи браузера), нажатием на слово добавить его в карточки или отметить «знаю», а ответ «как понял» двигает цель.

**Architecture:** чистый пакет `internal/texts` (`Stitch`, понимание, контроллер цели); обработчик собирает входы из базы (известные слова, целевые слова по частоте, примеры Tatoeba), сохраняет собранный текст в `texts` и отдаёт его со словарём подсказок; клиент рисует токены и озвучивает через `speechSynthesis`.

**Tech Stack:** Go, sqlc, goose, OpenAPI, React, Vitest, Playwright. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-10-26-smart-texts-design.md`.

## Global Constraints
- Без языковой модели: тексты собираются из уже загруженных предложений.
- Понимание считает `exercises.Coverage` по словам известным (`learned`, `known_at_start`) + служебные; числа и имена не в начале не в счёт. Цель `learn_preferences.text_coverage` 0,80–0,90, по умолчанию 0,85; результат склейки в пределах цели ± 0,05.
- Целевых слов в тексте 3–6; каждое не меньше двух раз в разных предложениях; предложение 4–12 слов; текст 6–10 предложений; без повторов предложений.
- Миграция на настоящую базу — только после «да» пользователя и `pg_dump`.
- Тексты и подсказки в интерфейсе выводятся только текстом (`dangerouslySetInnerHTML` запрещён). Звук: только `speechSynthesis`, без файлов.
- Известное ограничение для честности: склейка — связанные предложения, не рассказ; плашка с покрытием текста показывается всегда.

## Review Focus
- Пользователь с 0 известных слов: сервис не падает и не выдаёт пустой текст (объяснение «сначала знакомство/быстрый тест» или текст из самых частых слов).
- Нехватка предложений для целевого слова: слово пропускается, а не ломает сборку; если собрать нельзя — `404 no_text` с понятным текстом, не 500.
- Повтор запроса оценки по ключу не двигает цель дважды; чужой номер текста — 404.
- `speechSynthesis` недоступен (Firefox без голосов, тест-окружение): кнопки звука не показываются или отключены, чтение работает.
- Слово-имя, число, слово с апострофом и дефисом в тексте: нажатие не падает.

### Task 1: Склейка и контроллер цели (чистые функции)
**Files:** Create `internal/texts/stitch.go`, `target.go`, `stitch_test.go`, `target_test.go`.
**Interfaces:** Produces
- `type Sentence struct { ID int64; En, Ru string; Tokens []string }` (Tokens — `CasedTokens`),
- `type Candidate struct { Target string; Sentences []Sentence }` (предложения с этим целевым словом),
- `type Options struct { Goal float64; MinSentences, MaxSentences, MaxTargets int; Seed int64 }`,
- `type Text struct { Sentences []Sentence; Targets []string; Coverage float64 }`,
- `func Stitch(known map[string]bool, cands []Candidate, opts Options) (Text, bool)`,
- `func Understanding(tokens [][]string, known map[string]bool) float64`,
- `func NextGoal(current float64, understood string) float64` (`easy` → −0,02, `hard` → +0,02, `ok` без изменений, границы 0,80–0,90).
- [ ] Тесты (RED первыми): понимание считается как `Coverage` по всем токенам текста; `Stitch` — покрытие в пределах цели ± 0,05, 3–6 целевых слов, каждое ≥ 2 раз в разных предложениях, нет дублей предложений, предложения соседей делят содержательное слово, воспроизводимость по `Seed`, ослабление связности при нехватке (результат всё равно с честным `Coverage`), пустые входы → `false`; `NextGoal` на границах 0,80/0,90, неизвестная оценка.
