# Импорт Tatoeba (пары предложений англ.–рус.) — спек

Дата: 2026-10-23. Статус: ждёт одобрения пользователя. Ветка: `feat/tatoeba-import` (от `feat/word-search`; PR #1–#3 открыты, остальные ветки стоят цепочкой и на GitHub не отправлены).

## Цель

Загрузить в PostgreSQL пары предложений «английское — русский перевод» из Tatoeba: основу для примеров слов и упражнений. После подпроекта `go run ./cmd/import tatoeba` кладёт в базу около 806 тыс. предложений и 536 тыс. пар с авторами, источник виден на странице «Источники» с лицензией и атрибуцией. Повторный запуск ничего не дублирует. Каркас импортёра (`internal/importer`) не меняется: модуль подключается одной строкой регистрации.

Решение пользователя: пары берём с ManyThings (готовый файл со снимком), а не из официальных еженедельных выгрузок Tatoeba.

Не входит (следующие подпроекты): поиск примеров для слова и показ их на странице «Слова», полнотекстовый индекс, уровень предложения, упражнения.

## Источник

**ManyThings «Tab-delimited Bilingual Sentence Pairs», rus-eng**, данные из Tatoeba (`sentences_detailed.csv`). Страница: `https://www.manythings.org/anki/`.

- Файл: `https://www.manythings.org/anki/rus-eng.zip`, 17 447 329 байт, снимок от 13.02.2026 (поле `Last-Modified` и `_about.txt`), SHA-256 `1534e267976f43ae97e966d2ac9dc1e9128fdd0efdf08eceee21cd88ff20682c`. Файл статический: адрес не перезаписывается, как у официальных выгрузок Tatoeba (те обновляются каждую субботу).
- Внутри два файла: `rus.txt` (89 182 633 байта, 536 124 строки) и `_about.txt`. Нужен только `rus.txt`.
- Формат строки: `английское<TAB>русское<TAB>атрибуция`, где атрибуция имеет вид `CC-BY 2.0 (France) Attribution: tatoeba.org #<id английского> (<автор>) & #<id русского> (<автор>)`.
- Проверено разбором всего файла: во всех 536 124 строках ровно три поля и атрибуция по одному шаблону; пар уникальных 536 124; английских предложений 341 183, русских 465 439; один и тот же id всегда с одним и тем же текстом; управляющих символов, пробелов по краям и нелатинских «английских» строк нет; на одно английское приходится до 28 русских; медиана длины английского 6 слов, максимум 101.
- **Лицензия:** [CC BY 2.0 FR](https://creativecommons.org/licenses/by/2.0/fr/): использовать можно с указанием авторов и лицензии. Атрибуция по стандарту Tatoeba: номер предложения на tatoeba.org и автор. Часть предложений есть и под CC0, но мы её не выделяем.
- Скачанный файл и извлечённый `rus.txt` лежат в `.cache/` вне Git.

## Модуль `internal/sources/tatoeba`

Контракт `importer.Source` без изменений. Имя `tatoeba`, версия `2026-02-13` (дата снимка), URL закреплён.

- **Описание (`Describe`):** лицензия «CC BY 2.0 FR: нужно указывать авторов (у каждого предложения указан автор и номер на tatoeba.org) и лицензию»; атрибуция: «Предложения: Tatoeba (tatoeba.org), лицензия CC BY 2.0 FR; пары англ.–рус. собраны на manythings.org/anki (снимок 13.02.2026); автор и номер каждого предложения сохранены».
- **`Fetch`:** скачивает zip через `importer.Download` (HTTPS, сумма, лимит 40 МиБ), затем достаёт из него только `rus.txt`: имя сравнивается точно (никакого пути из архива, `..` и абсолютных имён), распаковка во временный файл рядом и переименование, лимит распакованного 200 МиБ (защита от zip-бомбы; превышение — ошибка без остатка файла). Нет `rus.txt` или он не обычный файл — ошибка. Возвращает путь к `rus.txt` в `.cache/sources/tatoeba/`.
- **`Parse`:** читает построчно потоком (строки до 1 МиБ), убирает `\r` в конце. Ошибки с номером строки: не три поля; недопустимый UTF-8 или нулевой байт; атрибуция не по шаблону; пустой текст; id не число или ноль. Пары, где английское предложение длиннее 30 слов, пропускаются (в снимке таких 18), остальные отдаются как `Row{EnID, EnText, EnAuthor, RuID, RuText, RuAuthor int64/string}`. Слова считаются по `strings.Fields`.
- **`Load`:** для пары вставляет (или находит) английское и русское предложение и саму пару. Известные id держатся в памяти запуска (≈ 806 тыс. записей), чтобы не повторять запросы для предложений, встречающихся в нескольких парах. Если одно и то же предложение (язык, id) встретилось с другим текстом или автором, это ошибка, а не молчаливая подмена.

## Схема БД (одна миграция `00003`, откат удаляет таблицы)

Через навык `db-migration`; миграция только добавляет таблицы, данные не меняет.

- `sentences`: `id bigint identity PK`, `lang text CHECK IN ('en','ru')`, `tatoeba_id bigint NOT NULL CHECK > 0`, `text text NOT NULL CHECK length 1–1000`, `author text NOT NULL CHECK length 1–64`, `word_count smallint NOT NULL CHECK > 0`, `source_id bigint NOT NULL → data_sources (RESTRICT)`, `created_at`. `UNIQUE (lang, tatoeba_id)`; индекс по `source_id`.
- `sentence_pairs`: `en_id → sentences (CASCADE)`, `ru_id → sentences (CASCADE)`, `source_id → data_sources (RESTRICT)`, `PRIMARY KEY (en_id, ru_id)`; индексы по `ru_id` и `source_id`. Язык строк `en_id` и `ru_id` проверяет загрузчик (составной внешний ключ не нужен).
- Запросы только в `queries/` (`UpsertSentence`, `UpsertSentencePair`), без сборки SQL строкой.
- Индекс для полнотекстового поиска по английским предложениям не создаём: его строят после загрузки данных в подпроекте с примерами.

## Загрузка и идемпотентность

Одна транзакция, построчно; любая ошибка откатывает всё. `row_count` равен числу загруженных пар (536 106 для текущего снимка). Повторный запуск той же версии выполняет те же upsert-ы и даёт те же числа строк, `imported_at` обновляется. Ожидаемое число записей: 806 586 предложений (341 165 английских и 465 421 русских) и 536 106 пар. Время измеряется на реальном запуске; если оно окажется неприемлемым (десятки минут), загрузка переводится на пакетную вставку без изменения контракта.

## Тесты и проверка

- Образец `testdata/sample.txt` на ~40 строк: повторы английских и русских предложений, несколько переводов одного, длинное английское (больше 30 слов), кавычки и кириллица, автор с точкой и дефисом. Zip для тестов собирается в самом тесте (`archive/zip`), в репозитории бинарников нет.
- Разбор: поля образца и счётчики (пропуск длинных, повторы); ошибки с номером строки (не три поля, чужая атрибуция, не UTF-8, нулевой байт, id не число, пустой текст); `\r` в конце; пустой файл.
- `Fetch` на TLS-сервере: успех; zip без `rus.txt`; имена `../rus.txt`, `/etc/rus.txt`, `dir/rus.txt` отклоняются; `rus.txt` больше лимита распаковки; неверная сумма; повторный запуск не качает заново; в кэше не остаётся временных файлов после ошибок.
- Запуск на настоящей БД во временной схеме: числа предложений и пар; двойной импорт даёт те же числа; ошибка в середине файла откатывает всё; у каждого предложения один автор и номер; общее английское предложение с несколькими переводами хранится один раз; конфликт текста для одного id — ошибка.
- Реальный импорт после явного «да» пользователя: миграция на локальную базу, `go run ./cmd/import tatoeba`, ожидаемые числа выше, повторный запуск без изменений, замер времени и размера таблиц; `go vet`, `go test -race ./...`, `golangci-lint run`, `git status` без `.cache/`. Страница «Источники» после импорта показывает Tatoeba.

## Риски

- ManyThings — сторонний сайт, снимок обновляется только вручную; при смене файла обновляются URL, сумма, версия и счётчики модуля. Запасной вариант — официальные выгрузки Tatoeba (потребуют менять контракт под несколько файлов).
- Качество Tatoeba неровное (в документе проекта это отмечено как риск): примеры будут отбираться по длине и уровню слов в следующих подпроектах.
- Объём: ≈ 806 тыс. предложений в базе; размер таблиц и время импорта проверяются на реальном запуске.
- Авторы лежат в данных, но их показ рядом с примерами остаётся за подпроектом примеров: пока примеры не показываются, обязательство по атрибуции выполняется общей записью на странице «Источники» и сохранёнными авторами.
