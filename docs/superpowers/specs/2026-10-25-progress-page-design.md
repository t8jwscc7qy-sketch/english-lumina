# Прогресс: часы до цели и прогноз по реальному темпу

## Зачем

Принцип продукта: «честный путь до цели: линия прогресса с прогнозом даты диапазоном». Сейчас страница «Прогресс» — заглушка, а прогноз на «Сегодня» считается по цели из настроек («90 минут в день»), а не по тому, как человек занимается на самом деле. Нужен экран, который показывает, сколько часов уже набрано, сколько ещё нужно до цели, и когда ты, судя по реальному темпу, до неё дойдёшь; а пока данных мало, честно говорит «собираю данные».

Решено с пользователем 2026-10-25: главное на странице — часы до цели и прогноз по реальному темпу, сверху прогноз, ниже график, темп и карта тем.

## Данные (сервер: факты, без расчёта прогноза)

`GET /api/v1/progress/overview` (чтение, 401 без входа, ничего не пишет). Считается из журнала событий (`card.reviewed`, `exercise.answered`) тем же подсчётом минут, что и «Сегодня» (`activity.DayMinutes`), окно 365 суток, сутки в часовом поясе настроек (без настроек UTC).

Ответ:
- `startedOn` (необязательное, `YYYY-MM-DD`): сутки первого занятия в окне; нет занятий — поля нет;
- `daysSinceStart` (целое): сколько суток прошло с `startedOn` до сегодня включительно (с одного занятия сегодня — 1; нет занятий — 0);
- `studiedMinutes` (число, десятые): всего минут занятий в окне;
- `paceMinutesPerDay` (число, десятые): средний темп за последние 14 суток, включая пустые сутки (делится всегда на 14, пока не прошло 14 суток — тоже на 14: честно занижает темп новичка, показывается только при `paceReady`);
- `paceReady` (булево): `daysSinceStart >= 14`;
- `daily` (массив): последние 90 суток от `today−89` до `today`, по записи на сутки без пропусков: `{ day, minutes, cumulativeHours }`, где `cumulativeHours` — часы занятий с начала окна до конца этих суток включительно (десятые).

Чистые функции в `internal/activity` (с тестами): `Pace(perDay map[Day]time.Duration, today Day, days int) time.Duration` и `CumulativeSeries(perDay map[Day]time.Duration, today Day, days int) []DayPoint`; `StartedOn` — самые ранние сутки из `perDay`.

## Прогноз (фронтенд, чистая функция рядом с `forecast.ts`)

`forecastFromPace(current, target, studiedMinutes, paceMinutesPerDay, paceReady, today)` →
- `{ kind: 'reached' }` — цель не выше уровня (как `forecastForward`);
- `{ kind: 'enough' }` — набрано не меньше нужных часов (см. правила);
- `{ kind: 'collecting', daysSinceStart }` — `paceReady = false`: «Собираю данные: дату покажу после 14 суток занятий»;
- `{ kind: 'idle' }` — `paceReady`, но темп 0 за последние 14 суток: «Сейчас занятий нет: назвать дату нельзя»;
- `{ kind: 'estimate', needed: Range (часы), remaining: Range (часы), days: Range, finishBy: {earliest, latest}, saveWithTenMore?: { weeks: number } }`.

Правила:
- нужные часы — диапазон из `forecast.ts` (часы Cambridge × поправка 1,5–2 на самостоятельную учёбу, без изменений);
- остаток = `max(0, нужные − набранные)` отдельно для нижней и верхней границы; набрано = `studiedMinutes / 60`;
- срок в сутках = остаток ÷ (темп/60); даты как в `forecastForward` (сутки округляются вверх);
- набрано не меньше верхней границы нужных часов (оба остатка 0) → `{ kind: 'enough' }`: «Набрано больше нужных часов: оцени уровень и подними цель», дата не называется; набрано между границами → оценка по остатку верхней границы, нижняя граница срока 0 суток (дата «уже можно»);
- подсказка «что изменить»: тот же расчёт с темпом +10 минут в день; `saveWithTenMore.weeks` — разница верхних границ сроков в неделях, округление до целых, показывается только если ≥ 1; при темпе, который уже превышает 240 минут в день, подсказки нет;
- нереальный темп (больше 240 минут в день) помечается как в `forecast.ts`.

Допущение (одна сноска на экране): считаются только минуты в сервисе; уровень «сейчас» выбран пользователем, поэтому часы в сервисе вычитаются из нужных.

## Интерфейс (`/progress`, заменяет заглушку; колонка до 4xl; без новых библиотек)

1. **Прогноз** (`.surface`, заголовок «Прогноз»): итоговая фраза по виду прогноза (оценка: «До B2 примерно 4–6 месяцев, к 12 марта – 9 июня»; сбор данных: счётчик «3 из 14 суток» и `XpBar`; простой; достигнуто), строка «Что изменить: +10 минут в день сократят срок примерно на 3 недели», сноска о допущении (14px приглушённым).
2. **Часы занятий**: линия накопленных часов за 90 суток (SVG вручную: цвета из токенов, подписи осей, отметки раз в 2 недели, без анимации), под ней `XpBar` из 20 сегментов «Набрано 14 ч из 280–370 ч» (нижняя и верхняя границы нужных часов). Для читалок график скрыт (`aria-hidden`), а таблица по дням лежит в сворачиваемом блоке «Данные по дням». Нет занятий: график заменён текстом «Начни сессию, и здесь появится линия».
3. **Темп**: «Средний темп за 14 дней: 23 мин в день» (при `paceReady`, иначе «Темп покажу после 14 суток занятий»), «Занимаешься с 12 октября», «Набрано: 14 ч 20 мин».
4. **Карта тем**: все темы с рейтингом из `GET /exercises/topics` по возрастанию рейтинга; название по-русски, рейтинг числом, надёжность («высокая / средняя / низкая» или «мало ответов», как в `WeakTopics`); у пяти самых слабых с достаточной надёжностью пометка «слабая тема» текстом.
- Состояния: загрузка, ошибка с «Повторить», 401 → вход. Числа с `tabular-nums`; часы и минуты по-русски («14 ч 20 мин»). `DESIGN.md` обновляется. Исполнитель фронтенда обязан вызвать навыки `impeccable`, `web-design-guidelines`, `emil-design-eng` (и `dataviz` для графика).

## Тесты

- Чистые функции Go: `Pace` (пусто = 0; полные 14 суток; пустые сутки считаются), `CumulativeSeries` (длина 90, без пропусков, монотонно, накопление идёт с начала окна), старт занятий.
- Прогноз (Vitest): сбор данных, простой, оценка по темпу, вычитание набранных часов (нижняя и верхняя границы отдельно), остаток 0, подсказка «+10» (экономия ≥ 1 недели и < 1), темп выше 240.
- Обработчик с поддельным хранилищем (пусто; несколько суток; часовой пояс; чужие события; 401) и на настоящей Postgres во временной схеме (события за несколько суток → `startedOn`, `daysSinceStart`, `daily`).
- Vitest страницы; Playwright (светлая и тёмная темы, 1440/1024/390 px, без горизонтальной прокрутки).

## Риски и ограничения

- Минуты считаются по паузам между ответами (как на «Сегодня»), а не по времени на экране; занятия вне сервиса не учитываются.
- Окно 365 суток: больше года истории не видно; `GET /progress/overview` тяжелее `/progress/today` (много событий), но вызывается только при открытии страницы.
- Темп за 14 суток — оценка: резкая смена режима занятий меняет прогноз.
- Прогноз часов Cambridge рассчитан на занятия с преподавателем; поправка 1,5–2 — допущение, не данные.
- Рейтинг тем накапливается по ответам: у новых тем «мало ответов».

## Вне рамок

Вехи и «вспышка успеха»; смена уровня; прогноз по отдельным темам; экспорт данных; настройка окна темпа.
