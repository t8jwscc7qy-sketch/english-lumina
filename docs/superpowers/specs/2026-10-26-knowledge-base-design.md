# Каркас базы знаний `kb` и источник Kaikki (Wiktionary)

Дата: 2026-10-26. Подпроект 0 плана `docs/methodology/learning-method.md` и `docs/methodology/sources-catalog.md`. Ветка: `feat/kb-core` (от `feat/learn-camp`, где лежат спеки). Номера миграций уточнятся при реализации: `00014` — `kb`, затем «Знакомство» и «Шпаргалки».

## Зачем

Сейчас каждый источник кладёт данные в свои таблицы (`word_translations`, `word_frequencies`, `lexeme_cefr`, `sentences`), а потребители склеивают их запросами с зашитыми именами источников (`freedict-eng-rus`, `frequencywords-ru`). Результат: шумные переводы («батюшка», «сосать»), нет произношения, формы слов считаются по правилам, нет смысловых связей. Каждое следующее улучшение (WordNet, звук, тексты) потребовало бы новых склеек.

Цель: одна **база знаний** `kb`, куда лучшее из всех источников собирается по правилам, **отдельно от данных пользователя**, быстро читается и допускает новые источники и новые языки без переделки приложения.

Критерии успеха первого шага:
1. Для слов из `lexemes` собраны переводы на русский с привязкой к значениям, произношение (IPA), формы слов и синонимы из Kaikki.
2. Контрольный список из 40 слов (`dad`, `kid`, `thin`, `clothes`, `blow`, `light`, `table`, …) получает ожидаемый основной перевод не менее чем в 90 % случаев; устаревшие и грубые значения не выбираются, если есть обычное.
3. Покрытие слов переводом по уровням не ниже сегодняшнего и по IPA не ниже порога, найденного замером (см. «Отчёт качества»). **Уточнение по замеру 2026-10-26:** прежние цифры (A1 93 %, A2 91 %, B1 89 %, B2 85 %, C1 71 %, C2 67 %) считались по другому определению (без служебных слов). По метрике сборки (все слова из `lexemes`, переводы только из старого словаря) базовые значения такие: A1 80,5 %, A2 88,3 %, B1 89,2 %, B2 86,1 %, C1 71,4 %, C2 68,4 %, контрольный список 30 из 40; пороги в коде берутся от этих значений.
4. Сборка воспроизводима (те же входные файлы дают те же строки), повторяема без потерь и **не трогает данные пользователя**.
5. Чтение «карточки слова для урока» — один запрос по индексу, не дольше 5 мс.

## Принципы

1. **Знания отдельно от пользователя.** Всё производное лежит в таблицах с префиксом `kb_`; её можно удалить и пересобрать, не затронув `cards`, `exercises`, `mistakes`, `events`, `settings`.
2. **Устойчивая идентичность слова.** Данные пользователя ссылаются только на `public.lexemes.id` (ключ слова — лемма и часть речи, уже уникален). Номера значений, переводов и строк `kb` при пересборке меняются, на них ссылаться нельзя.
3. **У каждой строки известен источник и лицензия** (`source_id` в `data_sources`): из этого строится страница «Источники» и возможность исключить данные с запрещающей лицензией.
4. **Сборка детерминированная и идемпотентная.** Одна транзакция: до фиксации читатели видят прежние данные (без `TRUNCATE`, который блокирует чтение: используется `DELETE` и вставка).
5. **Правила слияния — чистые функции с тестами**, константы в коде; новый источник — новый разбор и (при необходимости) правило поля, без изменений остального приложения.
6. **Не усложнять заранее.** В этот шаг не входят: сырые данные в БД «про запас», подмена целых версий базы, векторный поиск, генерация ИИ, внешние сервисы.

> **Решение при реализации (2026-10-26):** вместо отдельной схемы PostgreSQL `kb` используются таблицы с префиксом `kb_` в текущей схеме. Причина: тесты работают во временных схемах внутри той же базы, что и настоящая; отдельная схема `kb` была бы общей для всех, и откат миграции в тесте удалил бы настоящую. Изоляция от данных пользователя та же (отдельные таблицы, на них нет ссылок из пользовательских), резервная копия — `pg_dump -t 'kb_*'`.

## Слои

1. **Сырьё:** скачанные файлы в `.cache/sources/` (имя, контрольная сумма SHA-256, лицензия в `data_sources`). Для Kaikki: `raw-wiktextract-data.jsonl.gz` (2,9 ГБ; разобранный Викисловарь всех языков), на диске свободно 42 ГБ, распаковывать не нужно (потоковое чтение).
2. **Подготовка** (`cmd/kb-prepare kaikki`, медленный шаг, раз на новую версию файла или новый список слов): читает архив потоком, быстро отбрасывает строки не английского языка (`lang_code = "en"`) и слов, которых нет среди лемм `lexemes` (и форм «form-of», ведущих на них), разбирает оставшиеся и пишет компактный файл `.cache/kb/kaikki-en.<хеш>.jsonl` (десятки МБ). Цель по времени — не дольше 20 минут; замеряется.
3. **Сборка** (`cmd/kb-build`, быстрый шаг, минуты): читает подготовленный файл Kaikki и существующие таблицы (`lexemes`, `lexeme_cefr`, `word_frequencies`, `word_translations` как «старый» источник), применяет правила слияния и пишет в `kb`.
4. **Выдача:** таблицы `kb` с индексами, плюс готовая «карточка слова» (`kb_teaching_card`). Потребители читают только их.

## Таблицы `kb_*` (миграция `00014`, откат удаляет схему целиком: производные данные, потерь пользовательских нет)

| Таблица | Содержимое |
|---|---|
| `kb_build` | `id`, начало и конец, `status`, `schema_version`, версии и суммы источников (`jsonb`), показатели отчёта (`jsonb`) |
| `kb_sense` | значение: `id`, `lexeme_id`, `sense_no`, `gloss_en`, `tags text[]`, флаги регистра (`archaic`, `obsolete`, `dated`, `vulgar`, `offensive`, `slang`, `rare`, `informal`), `source_id` |
| `kb_translation` | `lexeme_id`, `sense_id` (может быть пуст), `lang` (`ru`), `text`, `score real`, `rank`, `chosen boolean` (до двух на слово и язык), `flags text[]`, `source_ids bigint[]` |
| `kb_pronunciation` | `lexeme_id`, `accent` (`us`, `uk`, пусто), `ipa`, `audio_ref` (имя файла Wikimedia Commons или пусто), `is_primary`, `source_id` |
| `kb_form` | `form`, `lexeme_id`, `tag` (индекс по `form`: поиск «форма → слово» заменяет правила `internal/words`; потребители переходят позже) |
| `kb_relation` | `lexeme_id`, `kind` (`synonym`, `antonym`), `other_lemma`, `other_lexeme_id` (может быть пуст) |
| `kb_lexeme_stat` | `lexeme_id`, `freq_count` (сумма по формам из `word_frequencies` и `kb_form`), `freq_rank` по лемме |
| `kb_teaching_card` | `lexeme_id`, `payload jsonb` (слово, часть речи, уровень, ранг, два перевода, IPA, ссылка на звук, формы, синонимы), `built_at` |

SQL только в `queries/kb.sql` через sqlc (схема-квалифицированные имена); сборка пишет пакетно (`COPY`/`pgx.CopyFrom`).

## Правила слияния (чистые функции, `internal/kb`)

**Перевод.** Кандидаты: переводы Kaikki с кодом `ru` (поле `translations`, значение — по `sense`) и переводы FreeDict (`word_translations`). Оценка кандидата:

`score = вес источника (Kaikki 3, FreeDict 1) + согласие (+2, если встречается в двух источниках) + частота русского слова (по рангу в списке frequencywords-ru: до 5000 +2, до 20000 +1, дальше или нет места −1) + положение значения (первое +1) − штрафы (пометки `archaic`/`obsolete`/`dated` −5; `vulgar`/`offensive` −5; `slang`/`rare` −2; несколько слов −1; латиница в переводе — отбрасывается)`.

Основным становится кандидат с наибольшей оценкой; вторым — следующий с другим текстом и (если известно) другим значением. Константы — стартовые, подбираются на контрольном списке; нет ни одного кандидата выше порога — у слова нет перевода (как сейчас). Перевод и значение остаются связанными: урок показывает определение значения.

**Произношение.** Kaikki (`sounds`): основной американский вариант, затем британский; IPA без слэшей и скобок; звук — имя файла Commons. Нет IPA у слова — запись пуста (запасной CMUdict — отдельный шаг).

**Формы.** Kaikki (`forms`): все формы со слов; нет формы — записей нет (правила `internal/words` остаются запасным путём).

**Синонимы и антонимы.** Kaikki (`synonyms`, `antonyms`); ссылки на слова из `lexemes` разрешаются в `other_lexeme_id`.

**Статистика слов.** Частота леммы — сумма по её формам (и по лемме), а не лучшая форма, как сейчас; ранг считается по этой сумме.

**Уровень CEFR** не пересобирается: остаётся правило «самый низкий среди источников» из `lexeme_cefr`.

## Отчёт качества (`kb-build` печатает и записывает в `kb_build`)

- Покрытие переводом и IPA по уровням, число слов без значений, число переводов с флагами.
- **Контрольный список:** `internal/kb/golden_test.go` (40 слов с ожидаемым основным переводом; список пишу я, ты проверяешь выборочно) — доля совпадений.
- Выборка из 50 случайных слов с выбранными переводами для чтения глазами (файл отчёта).
- Пороги в коде: покрытие переводом по уровням не ниже сегодняшнего; сборка с худшими показателями завершается ошибкой и **не фиксируется** (транзакция откатывается).

## Потребители (поэтапно, «душим старое»)

В этом шаге меняются два места, остальные остаются на старых таблицах:
1. **`GET /api/v1/words` и «Слова»:** у слова появляются `ipa`, до двух русских переводов и синонимы (если сборка есть); без сборки поля пусты и страница работает как раньше.
2. **«Сопоставление»:** перевод берётся из `kb_translation` (основной), а при пустой `kb` — из прежнего пути (`word_translations`, `PickTranslation`). Это включает улучшение качества переводов без остановки.
Дальнейшие переходы (формы вместо `internal/words`, «Знакомство», «Привал», шпаргалки) — в своих спеках.

## Источник Kaikki (`internal/sources/kaikki`, `cmd/import kaikki`)

- Записывается в `data_sources` как `kaikki-wiktextract`, версия — дата дампа Викисловаря (`2026-10-01` на момент написания), лицензия **CC BY-SA и GFDL** (как у Викисловаря; страница загрузок лицензию не называет, это надо подтвердить при реализации), атрибуция: «Wiktionary contributors, extracted by Wiktextract (Tatu Ylonen), kaikki.org; Tatu Ylonen, “Wiktextract: Wiktionary as Machine-Readable Structured Data”, LREC 2022».
- Файл на `kaikki.org` перезаписывается примерно раз в неделю и не имеет опубликованной суммы: сумму закрепляем сами при первой загрузке; если файл на сайте изменился, загрузка падает на проверке суммы, а обновление — осознанное действие (новая версия, новая сумма).
- Модуль реализует только `Fetch` и регистрацию источника через общий каркас; разбор и слияние идут в `kb-prepare` и `kb-build`.

## Тесты и проверка

- Юнит: разбор строки Kaikki (фикстура из ~20 записей: несколько значений, пометки `archaic`/`vulgar`, русские переводы по `sense`, звуки US/UK, формы, синонимы), отбор строк по языку и по списку лемм, оценка переводов (таблица, контрольный список), выбор IPA, статистика по формам, пороги отчёта.
- Обработчик с поддельным хранилищем: «Слова» с `ipa` и переводами и без них; «Сопоставление» берёт перевод из `kb`, при пустой `kb` — старый путь.
- Интеграционный на Postgres во временной схеме: миграция вверх и вниз; сборка из малых фикстур; повторная сборка не дублирует; сборка при падении порога не меняет данные; читатель во время сборки видит прежние данные.
- Живая проверка: полный прогон `kb-prepare` и `kb-build` на локальной базе (после `pg_dump`), время каждого шага, размер `kb`, отчёт качества, 50 слов глазами, контрольный список; «Слова» и «Сопоставление» на настоящем сервере. Файл ≈ 3 ГБ скачивается один раз и лежит в `.cache` (в git не идёт).

## Вне объёма

WordNet, звук Tatoeba, тексты (VOA, OneStopEnglish, Simple Wikipedia), картинки, русский Викисловарь, примеры из Kaikki, слова вне `lexemes` (Kaikki только обогащает известные слова), замена `internal/words`, «Знакомство» и «Привал», генерация ИИ.

## Ограничения и риски (заранее)

- Качество Викисловаря неоднородно: у редких слов переводов может не быть, у многозначных значения размечены по-разному; поэтому нужны контрольный список и проверка выборки человеком.
- Подготовка читает ≈ 25 ГБ распакованного текста потоком; время и память будут замерены, цель — не дольше 20 минут и постоянная память.
- Оценка переводов эвристическая и не откалибрована; константы подбираются по контрольному списку, который я составляю сам (поэтому его нужно проверить выборочно).
- Леммы в `lexemes` содержат варианты через слэш и точки (`colour/color`, `a.m.`): сопоставление с Kaikki берёт варианты по отдельности, часть слов останется без данных.
- Лицензия Kaikki и звуковых файлов Commons подтверждается при реализации; звук в этом шаге хранится только ссылкой (файлы не качаются).

## Итоги реализации (2026-10-26, отличия от первоначального текста)

- Вместо `cmd/import kaikki` скачивание, проверку суммы и регистрацию источника делает `cmd/kb-prepare kaikki` (общий каркас `importer.Run` считает пустой результат ошибкой и не подходит).
- Таблицы `kb_*` вместо схемы `kb` (см. решение выше); связь перевода со значением хранится как `sense_no` и только от Kaikki; логика слияния — чистая функция `kb.Assemble`; режимы `kb-build -dry-run` и `-explain`.
- Правила оценки уточнены по реальным данным: порядок групп переводов Викисловаря и порядок слов в группе, нумерация групп сквозь статьи по `etymology_number`, привязка пояснения к значению только при совпадении не менее 75 % значимых слов, пометки у лучшего вхождения слова, плавная шкала русской частоты, второй перевод не берётся грубым, устаревшим, диалектным и слабым, формы и синонимы фильтруются по пометкам. Первая версия правил (ступенчатая частота, значения по подстроке) давала на контрольном списке 25 из 40 хуже старого словаря (30 из 40); итог 40 из 40.
- Пороги качества выражены по метрике сборки (все слова из `lexemes`), а не по прежним цифрам без служебных слов: базовые значения старого словаря A1 80,5 %, A2 88,3 %, B1 89,2 %, B2 86,1 %, C1 71,4 %, C2 68,4 %.
- Записи `form-of` не отбираются: формы лежат в поле `forms` самой леммы.
- Измерено: подготовка 1 мин 20 с, сборка 3,8 с и ≈ 510 МБ, таблицы 66 МБ, чтение карточки 0,1 мс (цели из спека выполнены).
