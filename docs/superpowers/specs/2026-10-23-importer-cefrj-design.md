# Каркас импортёра и источник CEFR-J — спек

Дата: 2026-10-23. Статус: ждёт одобрения пользователя. Ветка: `feat/importer-cefrj` (от `feat/onboarding-settings`, PR #1 ещё не влит).

## Цель

Первый подпроект этапа «Импорт баз» проектного документа: общий каркас импортёра (контракт, реестр, команда, таблицы) и первый источник, список CEFR-J. После него команда `go run ./cmd/import cefrj` кладёт в PostgreSQL слова с уровнями A1–B2 и источник виден в `data_sources`. Повторный запуск ничего не дублирует. Следующие источники (Octanove C1/C2, Tatoeba, частоты) добавляются новым модулем без правок каркаса.

Решения пользователя: первым берём список CEFR; Octanove C1/C2 подключается отдельным подпроектом позже (у него другая лицензия, CC BY-SA 4.0).

Не входит: страница «Источники и лицензии» и API для неё, поиск слова, Tatoeba, частоты, Octanove, таблицы предложений и частот, нормализация вариантов написания.

## Источник

**CEFR-J Wordlist 1.5**, зеркало Open Language Profiles: `https://github.com/openlanguageprofiles/olp-en-cefrj`, файл `cefrj-vocabulary-profile-1.5.csv`. Официальная страница с версией 1.6: `https://www.cefr-j.org/download_eng.html`; берём зеркало, потому что оно отдаёт файл прямой ссылкой.

- Ссылка закреплена на коммит: `https://raw.githubusercontent.com/openlanguageprofiles/olp-en-cefrj/d4e45b75b38f27b30dfc5c44d8c571aec7e7092f/cefrj-vocabulary-profile-1.5.csv`. Ожидаемый SHA-256: `b0dd3c635f1c9a4fdf1490c7e5b7c48e8bbe55b652ad0c9860a95f98e10ae498`, размер 233 214 байт.
- Содержимое (проверено разбором файла): 7 799 строк, колонки `headword,pos,CEFR,CoreInventory 1,CoreInventory 2,Threshold`; уровни A1 1 164, A2 1 411, B1 2 446, B2 2 778; 15 значений `pos` (noun, adjective, verb, adverb, pronoun, preposition, determiner, conjunction, number, modal auxiliary, be-verb, interjection, do-verb, have-verb, infinitive-to); пары (headword, pos) уникальны; пустых обязательных полей нет; headword до 32 символов, встречаются варианты через слэш (`a.m./A.M./am/AM`, `cafe/café`).
- **Лицензия:** авторские права у Tono Laboratory, TUFS. Использование в исследованиях и в коммерции бесплатно с указанием источника (README зеркала); официальная страница добавляет, что при коммерческом использовании расходы согласуются отдельно. Личный некоммерческий сервис укладывается в оба текста. Если проект станет коммерческим, нужна договорённость с Tono Laboratory. Атрибуция (текст из `data_sources.attribution`): «The CEFR-J Wordlist Version 1.5. Compiled by Yukio Tono, Tokyo University of Foreign Studies.»
- Скачанный файл в Git не попадает (`.cache/` в `.gitignore`).

## Контракт и каркас

Пакет `internal/importer` (контракт, реестр, запуск) и модуль `internal/sources/cefrj/`.

- **Контракт `Source`:** `Describe()` возвращает имя (`cefrj`), версию (`1.5`), название лицензии, URL, текст атрибуции; `Fetch` скачивает файл в кэш и проверяет контрольную сумму; `Parse` разбирает файл потоком, не читая его целиком в память, и отдаёт строки по одной; `Load` пишет строки в базу в транзакции запуска. Точные сигнатуры решает план.
- **Реестр:** карта «имя → источник»; подключение нового источника — одна строка регистрации.
- **Запуск** (`importer.Run`): создаёт или находит запись в `data_sources`, вызывает `Fetch` → `Parse` → `Load` в одной транзакции, в конце записывает число строк и время. Любая ошибка откатывает всё; в базе не остаётся полузагруженного источника.
- **Команда** `cmd/import`: `go run ./cmd/import <имя>` запускает источник, `go run ./cmd/import list` показывает зарегистрированные. Настройки базы из `.env` через `config.Load`. Печатает имя, версию, число строк и время (`slog`); при ошибке выходит с ненулевым кодом.
- **Скачивание:** только HTTPS по закреплённой ссылке, таймаут, ограничение размера 10 МиБ, имя файла в кэше задано модулем, а не сервером. Файл лежит в `.cache/sources/cefrj/`. Контрольная сумма сверяется до разбора; несовпадение — ошибка, файл разбору не передаётся. Уже скачанный файл с верной суммой повторно не качается.
- **Разбор:** `encoding/csv`; пустой файл, неожиданные колонки, пустые `headword`/`pos`, неизвестный уровень (не из A1–C2), длина `headword` больше 64 — ошибка с номером строки. Значения `CoreInventory 1`, `CoreInventory 2`, `Threshold` складываются в `extra` только непустые.

## Схема БД (одна новая миграция `00002`, добавляющая таблицы; откат удаляет их)

Миграция создаётся через навык `db-migration`. Данные она не меняет и не удаляет, поэтому на локальную базу применяется после тестов на временной схеме.

- `data_sources`: `id`, `name text` (1–32), `version text` (1–32), `license text`, `url text`, `attribution text`, `row_count integer`, `imported_at timestamptz`, `created_at`; уникально по `(name, version)`.
- `lexemes`: `id`, `lemma text` (1–64), `pos text` (1–32), `source_id` → `data_sources` (`ON DELETE RESTRICT`, источник, впервые добавивший слово), `created_at`; уникально по `(lemma, pos)`.
- `lexeme_cefr`: `lexeme_id` → `lexemes` (`ON DELETE CASCADE`), `source_id` → `data_sources` (`ON DELETE RESTRICT`), `level text` с CHECK из A1…C2, `extra jsonb` (объект), первичный ключ `(lexeme_id, source_id)`.
- Запросы только в `queries/` через sqlc (`GetDataSource`, `UpsertDataSource`, `UpsertLexeme`, `UpsertLexemeCefr`, `FinishDataSource`), без сборки SQL строкой.
- `lemma` хранится как в файле, без разбора вариантов; нормализация понадобится поиску и делается в его подпроекте.

## Идемпотентность

Повторный запуск той же версии выполняет те же upsert-ы (`ON CONFLICT`) и даёт то же число строк в `lexemes` и `lexeme_cefr`. Новая версия источника получает новую запись в `data_sources` и новые строки в `lexeme_cefr`; старая версия остаётся как история (выбор актуальной версии — задача читающих запросов).

## Тесты и проверка

- Образец `internal/sources/cefrj/testdata/sample.csv` на ~30 строк (кавычки, слэш-варианты, `café`, `modal auxiliary`, пустые необязательные поля). Не настоящий дамп.
- Разбор: поля и `extra` образца; ошибки на пустом файле, чужих колонках, неизвестном уровне, пустом `headword`.
- Скачивание на `httptest`-сервере: успех; неверная сумма; ответ не 200; тело больше лимита; повторный запуск не качает заново.
- Запуск на настоящей базе во временной схеме: импорт образца, число строк в `lexemes` и `lexeme_cefr`; двойной импорт даёт то же число строк; ошибка на середине файла откатывает всё; запись `data_sources` заполнена.
- Общий помощник временной схемы выносится из `internal/httpapi/integration_test.go` в пакет `internal/testdb` и применяет все миграции по порядку, а не только `00001`; существующие тесты продолжают проходить.
- Реальный импорт: миграция на локальную базу, `go run ./cmd/import cefrj`, ожидаем 7 799 строк в `lexeme_cefr`, затем повторный запуск без изменения чисел; `go vet`, `go test -race ./...`, `golangci-lint run`.
- Скачанные данные в `git status` не попадают.

## Риски

- Зеркало на GitHub может исчезнуть или переехать: файл закреплён на коммит и сверяется по SHA-256; запасной вариант — официальная версия 1.6 с cefr-j.org (формат архива не подтверждён).
- Условия лицензии на коммерцию двусмысленны; пока сервис личный, это не мешает (см. «Источник»).
- В CEFR-J нет уровня C1: до подключения Octanove прогноз и упражнения для C1 слов не получат.
