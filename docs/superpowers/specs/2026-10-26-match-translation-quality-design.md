# Качество переводов в «Сопоставлении»: русские частоты

Дата: 2026-10-26. Ветка: `feat/match-translation-quality` (от `feat/exercises-match`).

## Проблема

`exercises.PickTranslation` (`internal/exercises/match.go`) выбирает русский перевод по правилу «вариант, который
встречается в наибольшем числе значений слова». На живых данных около трети наборов получают неудачные варианты:
`dad` — «батюшка», `kid` — «девчонка», `thin` — «редкий», `clothes` — «одёжа». Словарь FreeDict шумный, порядок
значений в нём не по частоте.

## Что нужно

Среди русских вариантов выбирать обычное слово, а не редкое или устаревшее. Критерий успеха: на словах `dad` и
`clothes` выбирается разговорный вариант (папа / одежда); `kid` и `thin` частотой не лечатся (см. ограничения); доля «хороших» наборов из 12 на живых
данных заметно выше прежних ~двух третей (оценка глазами, до и после на одних и тех же словах).

Допущения: словарь отдаёт русские леммы (начальные формы), они находятся в частотном списке как есть. Русский
список собран по формам слов из субтитров, поэтому разговорная лексика ранжируется выше книжной.

## Решение

### 1. Источник `frequencywords-ru`

Новый модуль `internal/sources/frequencywordsru` — копия `internal/sources/frequencywords` со своими константами:

- файл `ru_50k.txt` из `hermitdave/FrequencyWords`, ссылка закреплена на тот же коммит
  `525f9b560de45753a5ea01069454e72e9aa541c6` (`content/2018/ru/ru_50k.txt`), SHA-256
  `6095f507cc167488ec66ada5a85ac50433503a08ad24a07c6eabdf54352c4e7f` (сверено 2026-10-26, 50 000 строк);
- лицензия и атрибуция те же (CC BY-SA 4.0, Hermit Dave, OpenSubtitles2018), в тексте — `ru_50k`;
- `Parse` пропускает строки, где слово не из кириллицы и дефиса (в настоящем файле таких 1 181: «the», «you», смесь
  вроде «чтo» с латинской «o»); пропущенная строка занимает место, поэтому у остальных слов место равно номеру строки
  файла (первоначально здесь была ошибка с номером строки, но она роняла весь импорт);
- данные пишутся в существующую таблицу `word_frequencies` (ключ `source_id, word`); **миграции нет**, откатывать нечего.

Общий код с английским модулем не выносим (правило проекта: новый источник — новый модуль без правок остального).
Регистрируется в реестре импортёра: `go run ./cmd/import frequencywords-ru`.

### 2. Чтение рангов

Отдельный запрос не нужен: готовый `ListWordFrequencies(source_name, words[])` берёт места слов из последнего
завершённого импорта источника с заданным именем. Обработчик вызывает его один раз на набор с `frequencywords-ru`.

### 3. Правило выбора

`PickTranslation(senses [][]string, ranks map[string]int)`:

1. Кандидаты — те же, что сейчас (валидный однословный русский вариант).
2. Если `ranks` не пуст и у слова есть хотя бы один частый вариант (место не хуже `maxRuRank = 20000`), редкие и
   безместные варианты отбрасываются. Если частых нет — отсева нет (первоначальный жёсткий порог терял книжную
   лексику вроде «туризм», «местоимение», «морковь»; проверка на живых данных 2026-10-26).
3. Среди оставшихся: больше значений с вариантом, при равенстве прежний порядок словаря и алфавит. Место в списке
   при равенстве **не** используется: на живых данных (ревью 2026-10-26) оно давало плохие замены («рука» → «оружие»,
   «дуть» → «сосать»), потому что в субтитрах начальные формы и сленг ранжируются иначе, чем в учебной лексике.
4. Правило неоднозначности (несколько значений и ни один вариант не повторяется → `false`) считается и по
   исходным значениям: если отсев оставил одно значение, а у слова их несколько и консенсуса без отсева нет, решает
   прежнее правило без частот (`PickTranslation(senses, nil)`). Иначе частый, но случайный вариант принимался бы
   (`warm` → «сердечный», `can` → «задница»).
5. Если `ranks` пуст (источник не загружен) — прежнее поведение без изменений, не ошибка.

`maxRuRank = 20000` — константа, выбрана разумно, не откалибрована.

### 4. Интеграция

Места «ё» и «е» в списке стоят отдельно («теплый» 16 976, «тёплый» 24 601), словарь пишет через «ё»: обработчик
ищет обе записи и берёт лучшее место.

`internal/httpapi/exercises_pick.go` (около строки 448): после чтения переводов собрать множество кандидатов, одним
запросом прочитать их ранги, передать в `PickTranslation`. Контракт API и фронтенд не меняются.

## Известные ограничения (честно)

- Ранг не лечит все случаи: `thin` → «тонкий» (16 560) стоит в списке ниже «редкий» (12 922), `kid` и `clothes`
  зависят от того, что есть среди значений словаря («одёжа» в первых 50 000 нет, «одежда» — 2 865).
- Частота слова не означает верный перевод в данном значении; омонимы по-прежнему не различаются.
- Список по субтитрам: разговорная лексика завышена, формальная занижена.

## Тесты

- Юнит: `PickTranslation` с подставленными рангами — dad/kid/clothes, вариант без ранга, все варианты редкие (слово остаётся с прежним выбором), пустой `ranks` (старое поведение), равенство по числу значений решает ранг.
- Юнит: `Parse` нового источника — пропуск латиницы и смеси букв с сохранением мест, возрастание счёта, повтор слова, BOM, пустая строка.
- Интеграция (Postgres во временной схеме): импорт мини-файла, `ListWordFrequencies` берёт последнюю завершённую версию.
- Обработчик с поддельным хранилищем: набор строится при пустых и при непустых рангах.
- Живая проверка: импорт настоящего файла в локальную базу (разрешено CLAUDE.md, это обычный импорт без миграции),
  вывод выбранных переводов для 12 наборов до и после.

## Вне объёма

Лемматизация русского, ручные списки исключений, ранжирование по значению слова, банк ошибок для сопоставления.
