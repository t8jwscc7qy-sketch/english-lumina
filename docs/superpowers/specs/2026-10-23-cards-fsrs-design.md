# Словарь: карточки слов и интервальные повторения (FSRS) — спек

Дата: 2026-10-23. Статус: ждёт одобрения пользователя. Ветка: `feat/cards-fsrs` (от `feat/word-examples`; PR #1–#7 открыты стеком).

## Цель

Этап «Словарь» проектного документа: ежедневное повторение слов по алгоритму FSRS. Критерий готовности из документа: ежедневное повторение работает, интервалы покрыты тестами. Слово добавляется в карточки со страницы «Слова»; раздел «Карточки» показывает очередь на сегодня; «Сегодня» показывает настоящее число карточек к повторению. Каждое добавление и каждое повторение пишется в журнал событий.

Решения пользователя:
- алгоритм берётся из официальной библиотеки `github.com/open-spaced-repetition/go-fsrs/v4` (MIT, FSRS v6; новая зависимость одобрена);
- карточка — **пропуск в предложении**: английское предложение из Tatoeba без слова, русский перевод как подсказка; пользователь вспоминает слово, открывает ответ и оценивает себя (забыл / трудно / хорошо / легко).

Не входит: ввод слова с клавиатуры, голос, серии и «минимальный день» (этап «Прогресс и мотивация»), оптимизация параметров FSRS по журналу, упражнения и рейтинг Glicko.

## Решения исполнителя (v1)

- Суточного лимита новых карточек нет: пользователь сам решает, сколько добавлять.
- Очередь — по времени срока (`due`), показывается по одной карточке.
- Предложение для слова меняется от повторения к повторению: из до 5 примеров берётся номер `reps mod число_примеров`.
- Слово без подходящих примеров в карточки не добавляется (пропуск не из чего собрать). Если примеры исчезли уже после добавления, карточка показывается без предложения: слово и уровень.
- Параметры FSRS по умолчанию (`DefaultParam()`: удержание 0,9; максимальный интервал 36 500 дней); случайный разброс интервалов (fuzz) выключен, чтобы результат был воспроизводимым.
- Дней, часовых поясов и «границы суток» нет: срок — момент времени.

## Алгоритм: `internal/srs`

Тонкая обёртка над `go-fsrs/v4`: чистые функции, юнит-тесты, остальной код библиотеку не импортирует.

- `Card` — состояние, которое хранится в таблице: `Due, Stability, Difficulty, ScheduledDays, Reps, Lapses, State, LastReview, RemainingSteps` (поля карточки библиотеки v4).
- `New(now time.Time) Card` — новая карточка (состояние New, срок `now`).
- `Review(c Card, r Rating, now time.Time) (Card, error)` — применить оценку.
- `Preview(c Card, now time.Time) (map[Rating]time.Duration, error)` — через сколько вернётся карточка при каждой из четырёх оценок (для подписей кнопок).
- `Rating` 1–4 (Again, Hard, Good, Easy), любое другое значение — ошибка. Ошибки библиотеки превращаются в ошибки пакета.
- Тесты: инварианты, а не числа, скопированные из библиотеки: на новой карточке интервалы Again < Hard ≤ Good < Easy; «хорошо» поднимает стабильность, «забыл» на карточке в повторении увеличивает `Lapses` и переводит в переобучение; срок после оценки всегда позже `now`; повторение через настоящее время сходится по порядку (последовательность Good, Good, Good даёт растущие интервалы); недопустимая оценка и «ручная» оценка 0 — ошибка; отображение в поля таблицы и обратно без потерь.

## Схема БД (миграция `00005`, откат удаляет таблицу)

Через навык `db-migration`; миграция только добавляет таблицу.

`cards`: `id bigint identity PK`, `user_id → users (CASCADE)`, `lexeme_id → lexemes (RESTRICT)`, `due timestamptz NOT NULL`, `stability double precision NOT NULL CHECK >= 0`, `difficulty double precision NOT NULL CHECK >= 0`, `scheduled_days integer NOT NULL CHECK >= 0`, `reps integer NOT NULL CHECK >= 0`, `lapses integer NOT NULL CHECK >= 0`, `state smallint NOT NULL CHECK BETWEEN 0 AND 3`, `last_review timestamptz` (пусто, пока карточку не повторяли), `remaining_steps integer NOT NULL CHECK >= 0`, `created_at`, `updated_at`. `UNIQUE (user_id, lexeme_id)`; индекс `(user_id, due)` под очередь; индекс по `lexeme_id` под внешний ключ.

Запросы только в `queries/` через sqlc.

## Журнал событий

Таблица `events` уже есть (только добавление). Типы и полезная нагрузка (`schema_version` 1):
- `card.added`: `{cardId, lexemeId, lemma, pos}`; пишется только когда карточка действительно создана.
- `card.reviewed`: `{cardId, lexemeId, rating, stateBefore, stateAfter, dueAfter, scheduledDays, stability, difficulty}`; `occurred_at` — момент оценки.
- Ключ идемпотентности повторения: `review:<cardId>:<ключ клиента>`. Клиент создаёт новый ключ (UUID) для каждой показанной карточки и шлёт его с оценкой; повтор запроса (двойной клик, сетевой ретрай) не применяет оценку второй раз и возвращает ту же очередь.
- Обновление карточки и запись события — в одной транзакции; строка карточки блокируется (`FOR UPDATE`), чтобы две оценки не наложились.

## API (сначала `api/openapi.yaml`, затем генерация Go и TS)

Все ручки требуют сессию. Номер карточки идёт в теле запроса, а не в пути: параметры пути заставляют генератор добавить новую зависимость.

- `POST /api/v1/cards` — тело `{lemma, pos}`. Находит слово по точной паре (лемма, часть речи); если примеров для слова нет — 409 `no_examples`; слова нет — 404 `word_not_found`; создаёт карточку (`created: true`, 201) или возвращает существующую (`created: false`, 200). Ответ `{cardId, created}`.
- `GET /api/v1/cards/queue` — `{dueCount, totalCount, card}`, где `card` — следующая к повторению или `null`: `{cardId, lemma, pos, level, state, sentence, intervals}`; `sentence` — `{en: {text, author, tatoebaId}, ru: {…}, gap: {start, end}}` или `null`; `intervals` — `{again, hard, good, easy}` в секундах. В `sentence` попадают только предложения, где форма слова найдена (есть `gap`).
- `POST /api/v1/cards/review` — тело `{cardId, rating (1–4), key}`. Применяет оценку и возвращает ту же структуру, что и очередь (следующая карточка), чтобы не делать второй запрос. Чужая или несуществующая карточка — 404; недопустимая оценка, пустой ключ или ключ длиннее 64 символов — 400.
- В ответ поиска слов `Word` добавляется `inCards: boolean`.
- В enum кодов ошибок добавляются `no_examples` и `word_not_found`.

## Фронтенд

- **«Карточки»** (`/cards`, вместо заглушки): состояния — загрузка, «На сегодня всё» (когда очередь пуста), ошибка с «Повторить». Лицо карточки: предложение с пропуском (`_____` на месте слова), перевод как подсказка, кнопка «Показать ответ» (Пробел или Enter). Оборот: предложение целиком с подсвеченным словом, атрибуция Tatoeba (номер и автор со ссылками), четыре кнопки оценки «Забыл», «Трудно», «Хорошо», «Легко» (клавиши 1–4) с подписью, когда карточка вернётся («10 мин», «3 дн»). Счётчик «Осталось: N». Пока идёт запрос, кнопки заблокированы, ключ идемпотентности защищает от двойного отправления. Без предложения: слово, часть речи и уровень.
- **«Слова»:** у слова кнопка «В карточки»; у слов с `inCards` она показывает «В карточках» и неактивна; при 409 `no_examples` — понятное сообщение у кнопки.
- **«Сегодня»:** плитка «Карточки к повторению» показывает `dueCount` из очереди и ведёт в «Карточки»; остальное демо.
- Дизайн по `DESIGN.md`, после изменений обновить его. Весь текст по-русски на «ты». Подсветка и пропуск считаются в символах (кодовых точках).

## Тесты и проверка

- Go: юнит на `internal/srs`; хендлеры с фейковым хранилищем (401, неверный ввод, добавление создано/существует/нет слова/нет примеров, очередь пустая и с карточкой, оценка, повтор с тем же ключом); интеграционный на настоящей БД (добавление без дублей, очередь, состояния карточки после оценок, запись событий `card.added` и `card.reviewed` с нужной нагрузкой, идемпотентность повторения, чужая карточка, откат при ошибке записи события, `inCards` в поиске).
- Фронтенд: Vitest (состояния «Карточек», клавиатура, интервалы на кнопках, пропуск по диапазону с эмодзи, кнопка «В карточки», плитка на «Сегодня»); Playwright (сквозной сценарий: добавить слово → повторить с клавиатуры → «На сегодня всё»; снимки экранов в обеих темах на 1440, 1024, 390).
- Реальная проверка после явного «да» пользователя: миграция `00005` на локальную базу, добавление нескольких слов, цикл оценок через API на настоящих данных (ожидания: после «хорошо» срок позже, события в `events`).
- `go vet`, `go test -race ./...`, `golangci-lint run`, `npm test`, `tsc`, `oxlint`, сборка.

## Риски

- Новая зависимость `go-fsrs/v4`: при добавлении проверяется лицензия и транзитивные зависимости (в описании пакета их пять импортов), результат записывается в журнал выполнения.
- Параметры FSRS по умолчанию не подстроены под тебя; оптимизация по журналу — после накопления повторений (отдельная задача).
- Примеры Tatoeba бывают неудачными (неоднозначное слово в предложении): помогает смена предложения от повторения к повторению; возможность «пропустить это предложение» — не в v1.
- Омонимы не различаются при подборе предложений (ограничение подпроекта примеров).
- Покрытие примерами по уровням: A1 99 %, A2 97 %, B1 91 %, B2 74 %, C1 45 %, C2 19 %: часть слов старших уровней в карточки не добавить.
