# Вехи и «вспышка успеха»

## Зачем

Продукт называется Verst (от «версты», придорожного столба-вехи), а принцип мотивации записан в `PRODUCT.md`: «серия, вехи, никаких наказаний; игровое — вспышками в моменты успеха, остальное время спокойно». Сейчас серия и минимальный день есть, а вех и «вспышки успеха» нет. Этот цикл добавляет честные вехи из журнала событий и один спокойный праздничный момент в итоге дня.

Решено с пользователем 2026-10-25: вехи только из занятий (серия, часы, ответы, «первое»), без заявлений об уровне («A2 закрыт» не вводим: сервис уровень не проверяет).

## Список вех (фиксированный, в коде)

| Линейка (`kind`) | Пороги | Что считается |
|---|---|---|
| `streak` | 3, 7, 14, 30, 100, 365 дней | серия по правилам «Сегодня»: сутки подряд с минимумом 10 минут, один пропуск на 7 суток прощается |
| `hours` | 1, 5, 10, 25, 50, 100, 250 ч | накопленные часы занятий (минуты по паузам между ответами, как в «Прогрессе») |
| `answers` | 100, 500, 1000 | число событий `exercise.answered` и `card.reviewed` |
| `first` | карточка, упражнение, закрытая ошибка | первое событие `card.reviewed`, `exercise.answered`, `mistake.closed` |

Пороги серии больше 60 суток требуют окна длиннее 60: серия для вех считается по окну 365 суток (потолок «365 дней»). Часы и ответы тоже в окне 365 суток (то же ограничение, что у «Прогресса»).

## Данные и расчёт (сервер)

События те же, окно 365 суток, сутки в часовом поясе настроек (без настроек UTC). Чистые функции в `internal/activity` (с тестами):

- `StreakSeries(minutes map[Day]time.Duration, from, to Day) map[Day]int` — длина серии на конец каждых суток, повторным обратным подсчётом `ComputeStreakN` на конец каждых суток (воспроизведение вперёд расходится с обратным подсчётом): день с выполненным минимумом `+1`; пропущенный день прощается (серия не меняется), если с последнего прощённого пропуска прошло не меньше 7 суток, иначе серия обнуляется; после обнуления учёт начинается заново. Должна давать то же число на `to`, что и `ComputeStreak(minutes, to)`, с потолком окна (тест на случайных историях).
- `Milestones(...)` собирает ответ: для каждой вехи порог, `reachedOn` (первые сутки, когда значение достигло порога), `progress {value, target}` (текущее значение и порог для ближайшей недостигнутой вехи линейки; у достигнутой `value = target`).
- «Первое»: самые ранние сутки соответствующих событий в окне.

## API (сначала `api/openapi.yaml`)

`GET /api/v1/milestones` (чтение, 401 без входа) →
`{ milestones: [{ id, kind, title, threshold, reachedOn?, progress: { value, target } }], newToday: [string] }`.
- `id` стабилен: `streak-7`, `hours-10`, `answers-100`, `first-card`;
- `title` по-русски («Серия 7 дней», «10 часов занятий», «100 ответов», «Первая карточка»);
- `newToday` — `id` вех, у которых `reachedOn` равен сегодняшним суткам; ничего не хранится: после перезагрузки в тот же день они снова в списке.
- Без занятий все вехи не достигнуты, `progress.value = 0`, `newToday = []`, массивы не `null`.

## Интерфейс

- **Итог дня (`/session`)**: если `newToday` не пуст, над итогом карточка «Новая веха» (`.surface`, `role="status"`, `aria-live`): маскот «Верста» (пиксельный спрайт из `features/today/sprites`), название вехи, несколько вех — список, самая «крупная» (серия, затем часы, затем ответы) первой и крупнее. «Вспышка»: один раз при появлении, до 600 мс, ease-out, прозрачность и мягкий ореол из токенов (без новых цветов), при `prefers-reduced-motion` без движения (только появление). Звука и уведомлений нет.
- **«Прогресс»**: новый блок «Вехи» между «Часы занятий» и «Темп»: по каждой линейке достигнутые (название и дата, «7 дней подряд · 19 октября») и ближайшая недостигнутая с полосой `XpBar` («до 14 дней: 7 из 14»). Недостигнутое не красится в сигнальные цвета; ошибка загрузки вех не ломает страницу (блок скрывается с «Повторить»).
- `DESIGN.md` обновляется (вспышка успеха, блок «Вехи»). Исполнитель фронтенда обязан вызвать навыки `impeccable`, `web-design-guidelines`, `emil-design-eng` (движение: редкий праздничный момент допустим, остальное без движения).

## Тесты

- Чистые функции Go: `StreakSeries` против `ComputeStreak` на случайных историях (детерминированный генератор, не меньше 300 историй, окно 365), пороги часов и ответов, «первое», границы суток и часовой пояс, пустая история, веха ровно на пороге (`>=`).
- Обработчик с поддельным хранилищем (пусто; несколько вех; `newToday`; чужие события; 401; пояс) и на настоящей Postgres во временной схеме (события за несколько суток).
- Vitest: вспышка при `newToday` и её отсутствие без него; несколько вех; reduced-motion без движения; блок «Вехи» (достигнутые и ближайшая с полосой); ошибка загрузки; 401.
- Playwright: светлая и тёмная темы, 1440/1024/390 px, без горизонтальной прокрутки; итог дня с вехой.

## Риски и ограничения

- Окно 365 суток: значения считаются только по событиям окна. Серия больше 365 и часы или ответы, набранные до начала окна, не видны. Вехи, достигнутые до начала окна, показываются достигнутыми с датой внутри окна, и эта дата со временем сдвигается. Если самое раннее загруженное событие приходится на первые двое суток окна (история, вероятно, обрезана), `newToday` отдаётся пустым: вспышки нет, иначе она повторялась бы каждый день. Настоящее решение (событие `milestone.reached` или суточные итоги) отложено.
- Вехи считаются каждый раз заново из событий (до сотен тысяч строк у тяжёлого пользователя); вызываются при открытии итога дня и «Прогресса», не после каждого ответа.
- «Вспышка» после перезагрузки в тот же день показывается снова: история просмотров не хранится.
- Пороги и названия зашиты в код: смена порогов меняет прошлые вехи задним числом.

## Вне рамок

Вехи по уровням («A2 закрыт»); «босс недели»; уведомления; хранение «показано / не показано»; настройка порогов.
