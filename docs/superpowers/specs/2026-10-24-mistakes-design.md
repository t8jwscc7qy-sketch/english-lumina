# Банк ошибок: возврат ошибок и страница «Ошибки»

## Зачем

Принцип продукта: «ошибка — материал для работы, а не наказание: каждая возвращается в задания». Сейчас ошибка лишь немного снижает рейтинг темы, а само упражнение пропадает. Банк ошибок возвращает неверно решённое упражнение через день и закрывает его, когда пользователь ответил верно два раза подряд. Страница «Ошибки» (сейчас заглушка) показывает, что открыто и когда вернётся. Это же — готовый шаг для будущего «Маршрута дня» и источник событий для серий и вех.

Решено с пользователем 2026-10-24: возвращается то же упражнение плюс новое по теме (рейтинг темы работает как раньше); повтор через 1 день, затем через 3; закрытие после 2 верных ответов подряд; не больше 5 повторов в день; без обратного заполнения старых ошибок.

## Данные

Миграция `00010`:

- Таблица `mistakes`: `id`, `user_id` (ON DELETE CASCADE), `kind`, `sentence_id` (ссылка на `sentences`, ON DELETE RESTRICT), `topics text[]`, `payload jsonb`, `answer jsonb` (копии из исходного упражнения: строка самодостаточна), `given text` (последний неверный ответ), `streak smallint` 0–2, `status` (`open` | `closed`), `next_due timestamptz`, `first_wrong_at`, `closed_at` (NULL, пока открыта), `source_exercise_id bigint` (справочно, без внешнего ключа), `created_at`, `updated_at`.
- Не больше одной открытой ошибки на `(user_id, sentence_id, kind)`: частичный уникальный индекс по `status = 'open'`. Индекс для выборки повторов `(user_id, status, next_due)`.
- `exercises.mistake_id bigint` (необязательное, ссылка на `mistakes`, ON DELETE SET NULL): повтор — это новая строка `exercises` с этим полем.
- Down удаляет столбец и таблицу; данные банка при откате теряются (предупреждение в комментарии миграции).
- Применять к настоящей базе только с «да» пользователя и после `pg_dump`.

## Поведение

**Открытие.** В `AnswerExercise`, в той же транзакции, что и обновление рейтинга: неверный ответ на обычное упражнение создаёт ошибку `open`, `streak = 0`, `next_due = ответ + 1 день`; если открытая ошибка на то же предложение и вид уже есть, она сбрасывается (`streak = 0`, новый `next_due`), второй строки нет. Повтор запроса по ключу идемпотентности ничего не меняет. Пишется событие `mistake.opened` (только для новой строки).

**Повтор и закрытие.** Ответ на повтор (упражнение с `mistake_id`) идёт тем же путём:
- верно: `streak + 1`; при `streak = 1` `next_due = ответ + 3 дня`; при `streak = 2` ошибка закрывается (`status = closed`, `closed_at`, событие `mistake.closed`);
- неверно: `streak = 0`, `given` обновляется, `next_due = ответ + 1 день`.
Рейтинг темы обновляется как у любого ответа.

**Выдача.** `GetNextExercise` до выбора темы проверяет повторы: есть ли открытая ошибка с `next_due <= now`. Повтор выдаётся, если за сегодня (сутки в часовом поясе из настроек, по умолчанию UTC) повторов отвечено меньше 5 и два последних упражнения пользователя не были повторами. Выбирается самая старая по `next_due`. Если для этой ошибки уже есть неотвеченная копия, выдаётся она же (перезагрузка страницы не плодит строки). Иначе создаётся копия: тот же `kind`, `sentence_id`, темы, `payload` и `answer`, но `choices` у `gap`/`form` и плитки у `order` перемешиваются заново с условием, что порядок не совпадает ни с одним допустимым ответом (чистая функция `exercises.Reshuffle(choices или tiles, answers, seed)`). Правильный ответ клиенту по-прежнему не уходит.

## Контракт (сначала `api/openapi.yaml`)

- `GET /api/v1/mistakes` → `{ open: [Mistake], counts: { open, dueNow, closedThisWeek } }`; `Mistake`: `id`, `topic`, `kind`, `prompt`, `given`, `answer`, `streak`, `nextDue`, `firstWrongAt`. Отсортировано по `next_due`. Максимум 200 элементов; `counts.open` считает все.
- `Exercise.repeat` (boolean, необязательное): повтор ошибки.
- `AnswerResult.mistake` (необязательное): `{ status: "open" | "closed", streak, nextDue }` — для повтора и для нового неверного ответа.

## Интерфейс

- Страница «Ошибки» (заменяет заглушку): три числа («Открыто», «Ждут повтора сейчас», «Закрыто за неделю»); открытые ошибки по темам (название по-русски); строка: предложение (для `order` русский перевод), «Твой ответ: …», «Верно: …», «вернётся завтра» или «через 3 дня», серия «1 из 2». Пустое состояние: «Пока ошибок нет. Ошибки из упражнений появятся здесь и вернутся через день» (без чувства вины). Тексты из базы выводятся только текстом.
- Упражнения: над повтором приглушённый ярлык «Повтор ошибки»; в результате строка «Ошибка закрыта», «Ещё один верный ответ, и ошибка закрыта» или «Вернётся завтра».
- Движения нет (клавишные действия). `DESIGN.md` обновляется. Исполнитель фронтенда обязан вызвать навыки `impeccable`, `web-design-guidelines`, `emil-design-eng`.

## Тесты

- Чистые функции: `mistakes.Advance(m, correct, now)` (серия, `next_due`, закрытие), `exercises.Reshuffle`, правило выдачи (лимит 5, чередование, самая старая).
- `httpapi` с поддельным хранилищем: ошибка открывается; повторная ошибка на то же предложение сбрасывает, а не плодит; повтор выдаётся по расписанию и не чаще чем через одно обычное упражнение; тот же повтор при перезагрузке; закрытие после двух верных подряд; лимит 5; повтор запроса по ключу не двигает серию; 409 при другом ключе.
- Интеграция на настоящей Postgres во временной схеме: открытие → повтор через `next_due` → закрытие; частичный уникальный индекс; миграция up/down/up.
- Vitest и Playwright: страница «Ошибки» (светлая и тёмная темы, 1440/1024/390 px, без горизонтальной прокрутки), ярлык и строки результата у повтора.

## Риски и ограничения

- Ошибки считаются только с момента выхода; старые неверные ответы (в том числе тестовые) в банк не попадают.
- Расписание фиксированное (1 и 3 дня), не FSRS: так проще проверить и объяснить; переход на FSRS возможен позже.
- Копия упражнения привязана к тем же предложениям: ответ можно запомнить наизусть. Смягчение: перемешивание вариантов и плиток, а также новые задания по теме из обычного выбора.
- Досрочный повтор по кнопке не делаем: повтор идёт по расписанию.
- Неотвеченные копии не очищаются (как у `exercises` в целом).

## Вне рамок

«Маршрут дня», серии и «минимальный день»; досрочный повтор; ручное закрытие ошибки; обратное заполнение из событий; другие виды упражнений; перенос на FSRS.
