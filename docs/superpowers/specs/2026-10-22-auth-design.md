# Авторизация: вход одного пользователя

Дата: 2026-10-22. Статус: ждёт ревью пользователя.

## Цель

Единственный пользователь входит по логину и паролю. Сервер хранит сессию, в cookie лежит случайный токен, в БД только его SHA-256. Все будущие эндпоинты, кроме `/health`, закрыты проверкой сессии.

Вне объёма (YAGNI): веб-регистрация, смена пароля, «выйти везде», список сессий.

## Решения

- Первого и единственного пользователя создаёт команда `go run ./cmd/createuser` (веб-регистрации нет, поэтому сервер нельзя «занять» из сети).
- Пароль: argon2id, хеш в формате PHC (`$argon2id$...`), как требует `CHECK` в таблице `users`.
- Сессия: cookie `HttpOnly`, `Secure`, `SameSite=Strict`, срок 30 дней.
- Контракт сначала в `api/openapi.yaml`, затем генерация Go-кода через oapi-codegen.

## Контракт API

| Метод и путь | Запрос | Ответ |
|---|---|---|
| `POST /api/auth/login` | `{login, password}` | `204` + `Set-Cookie`; `401` при ошибке; `429` при блокировке |
| `POST /api/auth/logout` | — | `204`, сессия отозвана, cookie стёрта |
| `GET /api/auth/me` | — | `200 {login}` или `401` |

## Пакеты

- `internal/auth` — чистые функции с юнит-тестами:
  - хеширование и проверка пароля (argon2id);
  - генерация токена (32 случайных байта, base64url) и SHA-256 от токена.
- `internal/httpapi` — обработчики из сгенерированного интерфейса и middleware `RequireSession`, кладущий пользователя в контекст запроса.
- `cmd/createuser` — спрашивает логин и пароль (пароль без эха, `golang.org/x/term`) и пишет в БД через `CreateUser`. Если `UserExists` истинно, отказывает.
- Запросы к `users` и `sessions` уже есть в `queries/` и сгенерированы в `internal/db`.

## Безопасность

- Неверный логин и неверный пароль дают одинаковый `401`. Если логина нет, всё равно считается фиктивный хеш, чтобы по времени нельзя было отличить случаи.
- Ограничение перебора: счётчик неудач в памяти по IP, после 5 подряд — `429` на минуту.
- На POST проверяется заголовок `Origin` (защита от CSRF поверх `SameSite=Strict`).
- Пароль и токен не пишутся в логи.
- `TouchSession` продлевает `last_seen_at` не чаще раза в 5 минут (уже реализовано в запросе).
- `Secure`-cookie на `http://localhost` работает в Chrome и Firefox, в Safari нет; разработка в Chrome.

## Тесты

- Юнит-тесты `internal/auth`: хеш проходит проверку, неверный пароль отвергается, токены уникальны, хеш токена детерминирован.
- Тесты обработчиков через `httptest` (по образцу `health_test.go`): вход, неверный пароль, выход, `/me` без cookie.
- Проверка в запущенном приложении: `createuser`, затем `curl` вход, `/me`, выход.

- `golang.org/x/term` (ввод пароля)
- oapi-codegen (генерация кода)
