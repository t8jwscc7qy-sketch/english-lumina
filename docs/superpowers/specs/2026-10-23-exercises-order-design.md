# Упражнения, часть 2а: «порядок слов»

Дата: 2026-10-23. Ветка: `feat/exercises-order` (от `feat/exercises-gap`).

## Зачем

Часть 1 проверяет слово или грамматическую форму внутри готового предложения. «Порядок слов» проверяет другое умение: построить английское предложение из его частей по русскому переводу. Без LLM, на уже загруженных парах Tatoeba.

Остальные виды части 2 (выбор формы, перевод, сопоставление) — отдельные циклы «спек → план → реализация». Этот спек про один вид, `order`.

## Решения, согласованные с пользователем

- Ввод: клики по плиткам плюс клавиатура (без drag and drop и без новых зависимостей).
- Допустимые ответы: все английские предложения, связанные с тем же русским переводом, плюс само исходное.
- Тема рейтинга: новый ключ `skill:order` и `level:<уровень предложения>`; `skill:order` участвует в выборе слабой темы наравне с остальными, так что вид упражнения выбирается слабостью темы.
- Первое слово в плитках показывается в нижнем регистре, предложения с заглавными словами не в начале (кроме `I`) пропускаются.

## Данные

Миграция `00008` (обратимая): расширяет `exercises.kind` CHECK значением `order` (`DROP CONSTRAINT` + `ADD CONSTRAINT ... CHECK (kind IN ('gap','order'))`; Down возвращает `('gap')` — откат возможен, только если упражнений вида `order` нет, иначе Down падает с понятной ошибкой: в комментарии миграции предупреждение, что такие строки надо удалить). Существующие данные не меняются. **К настоящей базе применять только после явного «да» пользователя.**

`payload` вида `order`: `{prompt: "<русский перевод>", translation: "<русский перевод>", tiles: ["went","I","yesterday","home"], topic}`; `answer`: `{"answers": ["I went home yesterday.", "Yesterday I went home."]}` (допустимые предложения целиком, как в Tatoeba, с пунктуацией). `sentence_id` — исходное английское предложение.

## Чистые функции (юнит-тесты, без базы)

- `internal/exercises`: `BuildOrder(sentence string, alternatives []string, seed int64) (Order, bool)`.
  - Токены — слова предложения с пунктуацией, приклеенной к слову (`home.` остаётся `home.`), по пробелам. Длина 4–10 токенов; иначе `false`.
  - Предложение отбрасывается (`false`), если внутри есть токен с заглавной буквы, кроме `I` и его сокращений (`I'm`, `I'll`, `I've`, `I'd`); если в строке есть символы, при которых `len(strings.ToLower(s)) != len(s)`; если токенов больше 10 или меньше 4; если нет перевода.
  - Первый токен в плитках пишется с маленькой буквы (кроме `I...`). Завершающий знак препинания остаётся приклеенным к последнему слову предложения.
  - Плитки перемешиваются по `seed`; если порядок плиток совпал с исходным (и это не вырожденный случай одинаковых токенов), перемешивается заново, до 5 попыток, затем `false`.
  - `Order{Tiles []string, Answers []string}`; `Answers` — исходное предложение и допустимые альтернативы (альтернативы подаёт вызывающий; должны состоять из тех же токенов с точностью до регистра первого слова и порядка, иначе отбрасываются, чтобы плитки хватало на любой ответ).
- `internal/exercises.CheckOrder(answers []string, given string) bool`: нормализация (trim, схлопывание пробелов, регистр) и сравнение с каждым допустимым; `given` длиннее 200 символов — `false`. Можно повторно использовать `Check`.
- Тема: `exercises.OrderTopics(level string) []string` → `["skill:order", "level:<L>"]`.

## Подбор предложения

Расширение `GetNextExercise`:
- `skill:order` добавляется в выбираемые темы (вместе с 5 грамматическими и level). Если `PickTopic` выбрал `skill:order`:
  - кандидаты — окно `SampleSentences` (английские 4–10 слов с переводом), как для грамматики; уровень предложения — тот же правилом (max по CEFR, слово без уровня допустимо только с рангом ≤ 20000, апострофные токены нейтральны); уровень не выше уровня пользователя + 1 (в отличие от части 1 этот предел вводится сразу);
  - для кандидата ищутся альтернативы: все английские предложения, связанные с тем же русским предложением (`sentence_pairs.ru_id`), одним новым запросом `ListEnglishAlternatives(ruID)` (до 5, только 4–10 слов);
  - `BuildOrder`; если `false` — следующий кандидат; не более 30 кандидатов на окно.
- Предложение не повторяется (`UsedSentences` по теме `skill:order`).
- Если по теме ничего не нашлось, как в части 1 — следующая по слабости тема, не более 5 попыток, затем `404 no_exercise`.

## API (`api/openapi.yaml`, затем генерация)

- `Exercise.kind` enum: `[gap, order]`.
- `Exercise.tiles` (необязательный массив строк): только для `order`; для `gap` отсутствует. `prompt` для `order` — русский перевод (то, что нужно перевести), `choices` пустой.
- `POST /exercises/answer`: без изменений схемы. `given` для `order` — собранное предложение строкой (слова через пробел). Длина по-прежнему 1..200.
- `AnswerResult.answer` — первый допустимый вариант целиком; `translation` — русский перевод.
- Событие `exercise.answered` пишет `kind` и введённую строку.

## Интерфейс (`web/src/features/exercises/`)

- Страница выбирает компонент по `kind`: `GapExercise` (как сейчас) или `OrderExercise`.
- `OrderExercise`: русский перевод вверху; строка ответа (выбранные плитки по порядку); ниже перемешанные плитки. Клик по плитке переносит её в строку ответа; клик по плитке в строке возвращает её назад. Клавиши: цифры 1–9 и 0 (десятая) переносят соответствующую плитку из набора, `Backspace` возвращает последнюю, `Esc` очищает, `Enter` проверяет (когда использованы все плитки). После ответа — верно/неверно, показ правильного предложения целиком, рейтинги, «Дальше» (Пробел).
- Доступность: плитки — кнопки с доступными именами, `aria-keyshortcuts` у плиток, живой регион для результата (как у части 1), состояние «выбрано» не только цветом, `lang="en"` у английских плиток, фокус после загрузки на контейнере.
- Обновить `DESIGN.md` (плитка слова, строка ответа). Названия тем: `skill:order` → «Порядок слов».
- Навыки интерфейса (`impeccable`, `web-design-guidelines`, `emil-design-eng` для движения) вызываются при реализации — это требование проекта.

## Тесты

- Юнит: `BuildOrder` (обычное предложение, апострофы, дефис, повторяющиеся слова, заглавные слова, длина 3 и 11, перемешивание детерминировано по seed и не совпадает с исходным), `CheckOrder`, альтернативы с другими токенами отбрасываются.
- Ручка на fakeStore: выдача `order` (без правильного порядка в ответе, `tiles` перемешаны), ответ верный и неверный, альтернативный порядок засчитывается, 404 при отсутствии кандидатов, пул без подходящих предложений.
- Интеграционный на настоящей Postgres во временной схеме: выдача и ответ вида `order`, повтор по ключу, 409.
- Vitest: клики и клавиши, `Backspace`/`Esc`/`Enter`, нельзя проверить, пока не использованы все плитки, двойная отправка, ошибки ответа, доступность.
- Playwright с подменой API: сборка предложения клавишами, неверный порядок → показ правильного.
- Замер на настоящих данных (только чтение): запрос альтернатив и общий подбор кандидатов до 100 мс; число подходящих предложений длиной 4–10 слов с переводом по уровням.

## Вне объёма

Другие виды упражнений; перетаскивание; частичный зачёт за порядок; подсказки по первой плитке; ограничение времени.

## Риски

- Допустимых порядков бывает больше, чем найденных альтернатив: верный порядок может быть засчитан ошибкой. Смягчение: все связанные английские предложения, и показ правильного варианта после ответа. Остаточный риск записать в `CLAUDE.md`.
- Плитки с пунктуацией (`home.`) выдают последнее слово. Смягчение: знак остаётся приклеенным и к исходному, и к альтернативам, но тогда последнее слово видно по знаку; принято как допустимая подсказка.
- Короткие предложения (4 слова) могут давать мало осмысленных вариантов; порог 4 оставлен намеренно.
