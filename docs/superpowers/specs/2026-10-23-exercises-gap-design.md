# Упражнения, часть 1: «пропуск» и рейтинг по темам

Дата: 2026-10-23. Ветка: `feat/exercises-gap` (от `feat/frequency-list`).

## Зачем

Замкнуть цикл «измерить → найти слабое → точечная практика → измерить снова». Карточки учат слова, но грамматику и «чувство предложения» они не проверяют. Эта часть даёт первое упражнение и рейтинг по темам, на которых строятся следующие части.

Весь этап «Упражнения и адаптация» разбит на три части, у каждой свой спек и план:

1. **Это:** упражнение «пропуск», рейтинг Glicko-2 по темам, выбор слабой темы, события.
2. Остальные виды: порядок слов, перевод, выбор формы, сопоставление.
3. Банк ошибок, предложение сменить уровень, реальный темп в «счётчике срока».

## Решения, согласованные с пользователем

- Без LLM: всё строится из Tatoeba, CEFR и частот.
- Темы рейтинга бывают трёх видов: `level:A1`–`level:C2`, `pos:<часть речи>`, `grammar:<тема>`.
- Грамматическая тема определяется правилами по тексту предложения, небольшим набором.
- Упражнение создаётся при запросе и сохраняется в базе вместе с ответом (подход A). Банка заранее собранных упражнений и подписанных токенов нет.
- Новых зависимостей нет: Glicko-2 — формулы, пишутся самим.

## Данные

Миграция `00007` (обратимая, новые таблицы, существующие данные не трогает).

`exercises`
- `id bigserial PK`
- `user_id bigint NOT NULL REFERENCES users(id)` — упражнения личные; все запросы фильтруют по нему
- `kind text NOT NULL CHECK (kind IN ('gap'))`
- `sentence_id bigint NOT NULL REFERENCES sentences(id)` (английское предложение)
- `topics text[] NOT NULL` — ключи тем, по которым считается результат
- `payload jsonb NOT NULL` — то, что видит клиент: предложение с пропуском, перевод-подсказка, варианты, основная тема
- `answer jsonb NOT NULL` — верный ответ (допустимые написания); клиенту не отдаётся до ответа
- `created_at timestamptz NOT NULL DEFAULT now()`
- `answered_at timestamptz` — NULL, пока не отвечено

`topic_ratings`
- `user_id bigint NOT NULL`, `topic text NOT NULL` — составной первичный ключ `(user_id, topic)`
- `rating double precision NOT NULL DEFAULT 1500`
- `deviation double precision NOT NULL DEFAULT 350`
- `volatility double precision NOT NULL DEFAULT 0.06`
- `attempts integer NOT NULL DEFAULT 0`
- `updated_at timestamptz NOT NULL`

`events` не меняется: добавляется тип `exercise.answered` с данными `{exerciseId, kind, topics, correct, given, ratingBefore, ratingAfter}` (`given` — введённый текст, основа будущего банка ошибок). Идемпотентность — тот же механизм ключа, что у карточек; ключ события `exercise:<id упражнения>:<ключ клиента>`.

## Чистые функции (юнит-тесты, без базы)

- `internal/rating`: Glicko-2. `Update(r Rating, opponent Rating, score float64) Rating`. Соперник — сложность упражнения (`exercises.Opponent`): A1 = 800 … C2 = 1800 по ключу `level:*`, без него 1500, отклонение 100, волатильность 0,06. Проверка по примеру из статьи Глика.
- `internal/grammar`: `Topics(tokens []string) []string` — ключи `grammar:*` по словам предложения в исходном регистре (слово с заглавной не в начале предложения не даёт future/modals: «in May», «Call Will»; `IsTopicWord` отсекает и существительные «a can of», «my will»; сокращения вроде «I've» блокируют past_simple). `Interchangeable(a, b)` — группы взаимозаменяемых слов (may/might/could, over/above и т. п.). Набор v1: `articles` (a/an/the), `prepositions` (закрытый список из ~30 предлогов), `future` (will, going to), `modals` (can, could, must, should, may, might, would), `past_simple` (форма из таблицы неправильных глаголов `internal/words` или слово на `-ed`, без вспомогательного глагола перед ним). Есть и «слепая зона»: предложение без тем получает только `level:`/`pos:`.
- `internal/exercises`: `BuildGap(sentence, topic, tokens, seed) (Gap, bool)` и `BuildGapForWord(sentence, target, distractors, seed) (Gap, bool)` — выбор слова для пропуска, строка с пропуском, три–четыре варианта (правильный и до трёх отвлекающих: для артиклей — остальные артикли, поэтому вариантов три; для предлогов и модальных — слова темы, кроме взаимозаменяемых с ответом; для will — заведомо неверные is/been/to; для слов — формы и однотипные слова из `internal/words`; перед целью «a/an» отвлекающие начинаются на тот же тип звука, иначе предложение пропускается). В начале предложения варианты и `Answers[0]` пишутся с заглавной, чтобы совпадать дословно. `Check(answers, given) bool` (без учёта регистра и крайних пробелов, один из допустимых вариантов).
- Выбор темы: `PickTopic(ratings []TopicRating, available []string) string` — тема с наименьшим рейтингом, при равенстве с наибольшим отклонением; темы без попыток — первыми. Детерминированная, без случайности (случайность только при выборе предложения внутри темы).

## Выбор предложения

Уровень предложения = самый высокий уровень CEFR среди его слов (из `lexeme_cefr`, «уровень слова» — как в поиске). Если хоть одно слово предложения не имеет уровня и реже 20 000-го места в частотах (или вне списка), предложение не берётся. Длина 4–12 слов, перевод есть и короткий. Предложение не повторяется в теме после ответа на него (`UsedSentences` учитывает только отвеченные упражнения: обновление страницы предложения не сжигает). Слова с апострофом (don't, Tom's) для уровня нейтральны: ни дают уровень, ни отбраковывают.

Запросы лежат в `queries/exercises.sql` (параметры, без склейки). Отбор не обходит все 806 тыс. предложений: `SentenceIDRange` даёт границы номеров, `SampleSentences(from_id, max_rows)` читает окно подряд идущих английских предложений из 4–12 слов с самым коротким переводом начиная со случайного номера (при пустом окне повтор с нуля). Тему проверяет Go (`grammar.Topics`), уровни слов окна — одним запросом `SentenceLevels(words)`. Для `level:*`: `RandomLexemesByLevel(level, max_rows)` и поиск примеров слова. Рейтинги: `ListTopicRatings(user_id)`, `EnsureTopicRating` + `GetTopicRatingForUpdate(user_id, topic)` (так блокировать есть что даже у новой темы), `UpsertTopicRating`.

## API (`api/openapi.yaml`, затем генерация)

- `GET /api/v1/exercises/next` → `Exercise {id, kind, prompt, translation, choices[], topic}`. Без поля с ответом. Если подходящего не нашлось (в том числе пул предложений не пуст, но ни одно не даёт темы) — `404 {"error":{"code":"no_exercise",...}}`.
- `POST /api/v1/exercises/answer` тело `{exerciseId, given, key}` → `{correct, answer, translation, ratings[]}` (`answer` — написание как в вариантах; рейтинги затронутых тем после обновления). Повтор с тем же ключом возвращает тот же результат и ничего не пересчитывает. Ответ на уже отвеченное упражнение с другим ключом — `409`.
- `GET /api/v1/exercises/topics` → список тем с рейтингом, отклонением и числом попыток (для полосы «слабые темы»).
- Ошибки в обычном формате проекта. Номер упражнения передаётся в теле, не в пути (как у карточек).
- Транзакция при ответе: блокировка строки упражнения, `EnsureTopicRating` и блокировка рейтингов тем в отсортированном порядке, проверка, обновление `exercises.answered_at`, обновление `topic_ratings` всех тем, запись события — одной транзакцией (`httpapi.PgStore.InTx`).

## Интерфейс (`web/`, раздел «Упражнения»)

- Экран упражнения: предложение с пропуском, перевод-подсказка, три–четыре варианта (клавиши 1–4) или поле ввода (Enter). После ответа — верный ответ, перевод, кнопка «Дальше» (Пробел).
- Рядом полоса «Слабые темы»: пять тем с самым низким рейтингом.
- Сверка с `DESIGN.md`, стиль как у карточек; `DESIGN.md` обновляется. Текст интерфейса на русском, учебный контент на английском.
- Состояния: загрузка, нет упражнений (текст «Попробуй позже или поменяй уровень в настройках» со ссылкой на настройки, от карточек упражнения не зависят), ошибка сети, 401 ведёт на вход (в отличие от карточек, где это отложено).

## Тесты

- Юнит: `rating` (эталонный пример Glicko-2), `grammar` (по таблице «предложение → темы»), `exercises` (сборка, отвлекающие варианты, проверка ответа), `PickTopic`.
- Интеграционный на настоящей базе во временной схеме: выдача упражнения, ответ, повтор по ключу, `409`, события и рейтинги в одной транзакции.
- Сквозной Playwright с подменой API: ответ с клавиатуры, верный и неверный.
- Проверка на настоящих данных (копия или временная схема): число подходящих предложений по каждой теме и время запроса. Темы, где подходящих меньше сотни, в v1 не включаются.

## Вне объёма

Другие виды упражнений; предложение смены уровня; банк ошибок как экран; суточный лимит; серии и «минимальный день»; повторное прохождение ошибок; затухание рейтинга со временем (отклонение растёт по формуле Glicko-2 при простое, отдельной логики нет).

## Риски

- Грамматические правила по тексту неточны (`past_simple`, омонимы вроде `read`); поэтому набор маленький, а спорные предложения пропускаются, а не угадываются.
- Покрытие предложений по уровням C1–C2 низкое (у редких слов Tatoeba примеров нет), для них тем меньше. Это следствие данных, не баг.
- Запрос подбора предложений может оказаться медленным: проверяется планом запроса до реализации.
- a/the по переводу не различаются («I saw a dog» и «I saw the dog»): на артиклях возможны спорные ответы, полагаться можно только на контекст предложения.
- Группы взаимозаменяемых слов (`grammar.Interchangeable`) — ручной минимум; не вошедшие пары могут дать верный отвлекающий вариант.
