# English Pass

Личный веб-сервис для изучения английского: ведёт одного пользователя от текущего уровня к выбранной цели (A1 → C1) через цикл «измерить → найти слабое → точечная практика → измерить снова».

Источник истины по требованиям — проектный документ: https://claude.ai/artifact/KzboP3rVdfxNUrzBvHfWaU

## Статус

Этап 0 (окружение) закончен: есть Go-сервер с `GET /health` (`cmd/server`, `internal/httpapi`, `internal/config`), PostgreSQL в Docker. Остального кода ещё нет. Не описывай несуществующие файлы, команды и модули как готовые. Раздел «Команды» заполняется только командами, которые реально работают.

## Ключевые решения

- **v1 без LLM.** Упражнения строятся программно из импортированных баз (Tatoeba, CEFR, частоты). LLM — только после релиза v1.
- **Адаптация:** рейтинг Glicko по темам (рейтинг + уверенность), FSRS для карточек. Уровень выбирает пользователь; сервис сам подстраивает сложность, а смену уровня только предлагает.
- **Журнал событий** (`events`, только добавление) — источник для серий, вех, аналитики.
- **Внешние базы** импортируются в PostgreSQL. Каждый источник — модуль `internal/sources/<имя>/` с контрактом Fetch → Parse → Load + Describe. У каждой строки знаний есть `source_id`. Скачанные файлы не коммитятся.
- **Сначала десктоп**, вёрстка гибкая (без фиксированной ширины), чтобы телефон потом был доработкой.
- Интерфейс на русском, учебный контент на английском.

## Стек

- Backend: Go, `net/http`, pgx + sqlc, миграции goose, OpenAPI (`api/openapi.yaml`) → oapi-codegen, логи `slog`.
- Frontend (`web/`): React + TypeScript, Vite, Tailwind CSS, shadcn/ui, Motion, TanStack Query, Sonner.
- PostgreSQL в Docker Compose (Colima). Go-сервер при разработке запускается напрямую, не в контейнере.
- Git, удалённый репозиторий — публичный GitHub `english-lumina`. Всё в репозитории видно всем: ничего личного и секретного не коммитить.

Перед использованием библиотеки проверяй актуальное API через Context7, не полагайся на память.
Для навигации по Go и TypeScript (определения, использования, ошибки) используй LSP, а не grep. Интерфейс проверяй в браузере через Playwright.

## Правила кода

- Контракт API меняется сначала в `openapi.yaml`, затем генерируется код для Go и TypeScript. Генерированный код руками не правим.
- SQL только в `queries/` через sqlc; никакой конкатенации SQL-строк.
- Логика рейтинга, FSRS, генераторов упражнений и прогноза — чистые функции с юнит-тестами.
- Новый источник данных добавляется новым модулем импортёра, без правок остального приложения.
- Не добавляй зависимости без согласования с пользователем.

## Безопасность

- Секреты только в `.env` (в `.gitignore`); в репозитории — `.env.example`. Никогда не печатай и не коммить секреты.
- Пароль — argon2id; сессия в cookie `HttpOnly`, `Secure`, `SameSite=Strict`.
- Валидация входных данных на сервере; `dangerouslySetInnerHTML` запрещён.
- Миграции, удаляющие или меняющие данные, не применять без явного подтверждения пользователя и без `pg_dump`.

## Git

- Не коммить и не пушить без просьбы пользователя.
- Маленькие осмысленные коммиты; перед коммитом — тесты и линтеры.
- Не коммитить: `.env`, скачанные базы, кэш импорта, `node_modules`, сборки.

## Порядок работы

1. План: для задачи больше одного файла — короткий план и согласование.
2. Реализация маленькими шагами.
3. Проверка: тесты, линтеры, запуск приложения. Без запуска не заявлять «работает».
4. Ревью изменений перед тем, как сказать «готово».

Задача готова, когда: тесты проходят, линтеры чистые, секретов в коде нет, изменение проверено в запущенном приложении, миграции обратимы или согласованы.

## Модели

Проект работает на `opusplan`: Sonnet 5.5 выполняет, Opus 5.5 включается в режиме планирования.

- Поиск файлов и символов отдавай агенту `Explore` (Haiku).
- Стандартные задачи (функции, тесты, обычные баги, SQL, рефакторинг) делай сам на Sonnet.
- Если задача сложная (архитектура, трудная отладка, изменения в нескольких подсистемах, безопасность, миграции с данными, дизайн-система), **предложи** пользователю план-режим или `/model opus`. Модель молча не переключай.
- Агент `reviewer` (Opus) запускай только по просьбе пользователя или перед завершением большой/рискованной задачи, и не чаще одного раза на задачу.
- Субагентам передавай только нужный контекст. Маленькие правки не делегируй.

## Навыки для интерфейса

Навыки не дублируют друг друга, у каждого своя роль:
- `impeccable` — направление дизайна, дизайн-система, создание и критика экранов. Основной.
- Навыки Эмиля (`animate`, `review-animations` и др.) — анимации и полировка движения.
- `web-design-guidelines` — финальная проверка готового кода по чек-листу (доступность, фокус, формы). Не для выбора дизайна. Правила английской типографики (Title Case, кавычки) к русскому интерфейсу не применять.

`grill-me` — по запросу пользователя «прожарить» план или решение вопросами.

## Команды

Добавлять только проверенные команды.

Окружение (проверено):

- `colima start` — запустить Docker-движок (после перезагрузки Mac).
- `docker compose up -d --wait` — поднять PostgreSQL 17 (порт 5432, только localhost).
- `docker compose down` — остановить (данные сохраняются; флаг `-v` запрещён в deny).
- `go run ./cmd/server` — запустить сервер (читает `.env`, порт `HTTP_ADDR`, по умолчанию :8080); проверка: `curl localhost:8080/health`.
- `go vet ./... && go test -race ./...` — проверка кода и тесты.
- `.env` создаётся из `.env.example` с случайным паролем: `sed "s/change-me/$(openssl rand -hex 16)/g" .env.example > .env && chmod 600 .env`.
