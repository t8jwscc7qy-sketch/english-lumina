# English Pass

Личный веб-сервис для изучения английского: ведёт одного пользователя от текущего уровня к выбранной цели (A1 → C1) через цикл «измерить → найти слабое → точечная практика → измерить снова».

Источник истины по требованиям — проектный документ: https://claude.ai/artifact/KzboP3rVdfxNUrzBvHfWaU

## Статус

Проверено: юнит-тесты, интеграционный на Postgres во временной схеме, Vitest 357, Playwright 123; в настоящем браузере под реальным входом страница и ответ API совпали с событиями в базе (3 суток занятий, 6,3 мин, «Собираю данные»), состояние «оценка с подсказкой» вживую проверено в песочнице на событиях за 21 сутки (темп 27,5 мин, срок 38–51 месяц). НЕ проверено вживую на данных пользователя: оценка с датой (появится после 14 суток занятий). Известные ограничения: минуты по паузам между ответами, занятия вне сервиса не учитываются; окно истории 365 суток: набранные часы считаются только за окно, поэтому через год занятий они перестают расти и дата финиша перестаёт приближаться, пока не добавлены суточные итоги или запрос за всю историю; при темпе, дающем срок больше 10 лет, вместо даты показывается «При таком темпе срок больше 10 лет»; темп за 14 суток резко меняется при смене режима; прогноз Cambridge рассчитан на занятия с преподавателем (поправка — допущение); на «Сегодня» прогноз по-прежнему считается по цели из настроек, а не по реальному темпу; карта тем показывает все темы без группировки. Вехи и «вспышка успеха» (спек и план в `docs/superpowers/`, ветка `feat/milestones`): `GET /api/v1/milestones` считает вехи из журнала событий (окно 365 суток, часовой пояс настроек, миграций и новых запросов нет): серия 3, 7, 14, 30, 100, 365 дней, часы занятий 1, 5, 10, 25, 50, 100, 250, ответы 100, 500, 1000, «первое» (карточка, упражнение, закрытая ошибка); `reachedOn` — первые сутки, когда порог достигнут, `newToday` — достигнутые сегодня (серия, затем часы, затем ответы, затем первое; внутри линейки больший порог первым). Серия считается обратным подсчётом на каждые сутки (`StreakSeries` вызывает `ComputeStreakN` с потолком 400, совпадает с «Сегодня» по построению; прямой подсчёт расходится: прощается более ранний пропуск, а не более поздний). Экран: блок «Вехи» на `/progress` (достигнутые с датой, ближайшие по линейкам с полосой) и «вспышка» в итоге дня `/session` (маскот «Верста», 600 мс, только при `motion-safe`; после перезагрузки в тот же день видна снова, потому что считается из событий). Проверено: юнит-тесты, расчёт на 22 000 событий за 365 суток за 10–40 мс, интеграционный на Postgres во временной схеме, Vitest 378, Playwright 135 (дважды); в настоящем браузере под реальным входом блок «Вехи» совпал с базой (первая карточка 24 октября, первое упражнение 23 октября, «100 ответов: 81 из 100»), «вспышка» проверена вживую в песочнице на вставленных событиях (10 часов занятий и первая закрытая ошибка в тот же день). НЕ проверено вживую на данных пользователя: вспышка (новых вех сегодня у него нет). Известные ограничения: окно 365 суток (серия больше 365 и часы вне окна не считаются; вехи, достигнутые до окна, показываются достигнутыми с датой, которая сдвигается, а при обрезанной истории `newToday` пуст и вспышки нет), пороги зашиты в код (смена порогов меняет прошлые вехи задним числом), уровни («A2 закрыт») и «босс недели» не вводились, история просмотров вспышки не хранится. ## Ключевые решения

- **v1 без LLM.** Упражнения строятся программно из импортированных баз (Tatoeba, CEFR, частоты). LLM — только после релиза v1.
- **Адаптация:** рейтинг Glicko по темам (рейтинг + уверенность), FSRS для карточек. Уровень выбирает пользователь; сервис сам подстраивает сложность, а смену уровня только предлагает.
- **Журнал событий** (`events`, только добавление) — источник для серий, вех, аналитики.
- **Внешние базы** импортируются в PostgreSQL. Каждый источник — модуль `internal/sources/<имя>/` с контрактом Fetch → Parse → Load + Describe. У каждой строки знаний есть `source_id`. Скачанные файлы не коммитятся.
- **Сначала десктоп**, вёрстка гибкая (без фиксированной ширины), чтобы телефон потом был доработкой.
- Интерфейс на русском, учебный контент на английском.

## Стек

- Backend: Go, `net/http`, pgx + sqlc, миграции goose, OpenAPI (`api/openapi.yaml`) → oapi-codegen, логи `slog`.
- Frontend (`web/`): React + TypeScript, Vite, Tailwind CSS, shadcn/ui, Motion, TanStack Query, Sonner.

- Git, удалённый репозиторий — публичный GitHub `english-lumina`. Всё в репозитории видно всем: ничего личного и секретного не коммитить.

Перед использованием библиотеки проверяй актуальное API через Context7, не полагайся на память.
Для навигации по Go и TypeScript (определения, использования, ошибки) используй LSP, а не grep. Интерфейс проверяй в браузере через Playwright.
