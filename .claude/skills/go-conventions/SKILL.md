## Go

- Простота важнее хитрости. Ранний `return`, вложенность не глубже 3–4 уровней, функции до ~50 строк.
- Ошибки не игнорировать (`_` только осознанно). Оборачивать с контекстом: `fmt.Errorf("загрузка карточки: %w", err)`. Проверять через `errors.Is` / `errors.As`, не через `==`. Тексты ошибок в нижнем регистре, без точки.
- `panic` не для управления потоком.
- `context.Context` первым параметром, не хранить в структурах. `cancel` вызывать через `defer`.
- У каждой горутины есть путь к завершению (`ctx.Done()`). Несколько связанных горутин с ошибками — `errgroup` (новая зависимость, согласовать).
- Сервер завершается по сигналу: `signal.NotifyContext` + `Server.Shutdown` с таймаутом.
- Интерфейсы маленькие и объявляются там, где используются. Принимать интерфейсы, возвращать конкретные типы.
- Без изменяемых глобальных переменных: зависимости через конструктор.
- Не смешивать приёмники по значению и по указателю в одном типе.
- Имена пакетов короткие, строчные, без подчёркиваний.
- Тесты табличные. Чистые функции (рейтинг, FSRS, генераторы, прогноз) тестируются без БД. Запуск: `go test -race ./...`, плюс `go vet`.
- Логи только через `slog`. Секреты и пароли в логи не писать.

## Безопасность (из ревью Go)

- SQL только через sqlc и параметры, без конкатенации.
- Пути из внешнего ввода: `filepath.Clean` и проверка префикса.
- `os/exec` с пользовательским вводом не использовать без явной проверки.
- `InsecureSkipVerify: true` запрещён.

## PostgreSQL

- ID: `bigint` (identity), для строк `text`, для времени `timestamptz`, для флагов `boolean`.
- Индекс на каждый внешний ключ, по которому делают выборки или join. В составном индексе сначала колонки с равенством, потом с диапазоном.
- Частичные индексы для «живых» строк (`WHERE deleted_at IS NULL`). GIN — для `jsonb` и полнотекстового поиска.
- Пагинация курсором (`WHERE id > $1 ORDER BY id LIMIT n`), не `OFFSET`.
- Upsert: `INSERT ... ON CONFLICT DO UPDATE`. Импорт баз должен быть идемпотентным (повторный запуск не дублирует данные).
- Избегать N+1: выбирать связанные строки одним запросом.
- Для долгих операций задавать `statement_timeout`.
- Миграции — по навыку `db-migration`.
