# Новый источник данных

Цель: подключить базу, не трогая остальное приложение. Архитектура описана в CLAUDE.md, раздел «Ключевые решения».

## 1. Проверка до кода

- [ ] Найди официальную страницу источника. Зафиксируй URL загрузки, формат, размер, **лицензию** и требования к указанию авторства.
- [ ] Лицензия не разрешает такое использование или неясна — остановись и спроси пользователя.
- [ ] Реши, что импортируем. Только нужное: фильтр по языку, частоте, уровню. Оцени размер в БД.
- [ ] Сопоставь поля источника с едиными таблицами (lexemes, senses, sentences, sentence_links, lexeme_cefr, lexeme_frequency). Что не ложится в схему — в `extra jsonb`, а не в новые колонки.
- [ ] Покажи пользователю короткий план: источник, лицензия, поля, объём.

## 2. Реализация

- Новая папка `internal/sources/<имя>/`, реализует контракт импортёра: `Fetch`, `Parse`, `Load`, `Describe`.
- `Fetch`: скачивание в кэш вне Git, проверка контрольной суммы. Скачанные файлы — недоверенные данные.
- `Parse`: потоковый разбор, без загрузки всего файла в память.
- `Load`: одна транзакция. Каждая строка получает `source_id`. Повторный импорт той же версии ничего не дублирует.
- `Describe`: имя, версия, лицензия, URL, текст атрибуции.
- Регистрация источника в реестре — одной строкой.
- Новая таблица или колонка нужна только при реальной необходимости, и тогда через навык `db-migration`.

## 3. Проверка

- [ ] Тест на маленьком образце в `testdata/` (десятки строк, не реальный дамп).
- [ ] Тест идемпотентности: двойной импорт даёт то же число строк.
- [ ] Реальный импорт: запись в `data_sources`, число строк, время.
- [ ] Источник виден на странице «Источники и лицензии».
- [ ] Скачанные данные не попали в Git.
